# Argo local workdir rollout

## Goal

Move only short-lived Argo workflow workdirs from Hetzner Cloud volumes to
worker-local storage. Stateful platform data stays on `hcloud-volumes`.

The June 2026 invoice contained 13,133 short-lived 10 GB volumes generated by
the mctl-agents workflows. They cost EUR 10.53 of the EUR 19.92 volume total.
The dedicated `argo-workdir-local` StorageClass removes that per-run cloud
volume while retaining explicit PVC lifecycle management.

## Interfaces and assumptions

- `argo-workdir-local` is non-default and can only provision on the three CX43
  workers listed in `local-path-config`.
- Its provisioner identity is `mctl.ai/argo-workdir-local`, deliberately
  distinct from the k3s packaged controller's `rancher.io/local-path`, so the
  controllers cannot race for each other's claims.
- Each PV is a `hostPath` on `/var/lib/mctl/argo-workdir` and becomes pinned to
  the first consumer's node. It cannot be reattached to another worker.
- A worker drain or failure after the first bind can leave a later workflow pod
  Pending. The workflow must be terminated and rerun after the worker is
  restored; local-path does not provide transparent failover.
- ResourceQuota limits requested capacity, not actual filesystem usage.
  local-path-provisioner does not enforce project quotas inside the directory.
- `volumeClaimGC: OnWorkflowCompletion`, StorageClass
  `reclaimPolicy: Delete`, and the provisioner's teardown helper form the
  cleanup chain. A broken controller or helper can still leave data on disk.
- On SELinux-enabled MicroOS workers, only the provisioner helper pod uses
  `spc_t` so it can create and remove the host directory. Workflow workload
  pods retain their normal confined SELinux domain.
- Physical smoke-test databases are deliberately retained. Workflow retirement
  removes GitOps, ExternalSecret, and Vault references but the CNPG database
  remains for explicit database-retention policy and later controlled cleanup.

## Safety controls

- Namespace quota: 48 GiB requested local workdir storage.
- Warning and critical quota alerts: 80% and 95%.
- Root disk alerts: 70% warning and 90% critical.
- Node exporter uses the MicroOS SELinux `spc_t` type with root UID, but no
  Linux capabilities, no privileged mode, no privilege escalation, no
  service-account token, read-only rootfs, and read-only host mounts. The
  default `container_t` type denies `/host/proc/1/mountinfo` and disables the
  entire filesystem collector. A dedicated critical alert detects collector
  failure so disk-capacity alerts cannot be silently blind.
- A 10-minute Pending alert joins workflow pods to PVCs whose StorageClass is
  exactly `argo-workdir-local`.
- No fallback path exists for unlisted nodes. The CX33 control plane cannot
  receive local workdir volumes.
- CI validates the exact worker allow-list, WFFC/Delete semantics, quota,
  canary, and alert joins.

## Rollout

### 1. Foundation

Deploy the provisioner, StorageClass, quota, alerts, and
`argo-local-workdir-canary`. Do not switch any production ClusterWorkflowTemplate.

Run the normal canary:

```sh
kubectl create -n argo-workflows -f - <<'EOF'
apiVersion: argoproj.io/v1alpha1
kind: Workflow
metadata:
  generateName: argo-local-workdir-canary-
spec:
  workflowTemplateRef:
    name: argo-local-workdir-canary
    clusterScope: true
EOF
```

Acceptance:

- workflow succeeds;
- PVC binds to `argo-workdir-local`;
- PV node affinity names one of the three CX43 workers;
- writer and reader report the same node;
- workflow completion deletes PVC, PV, and the backing directory;
- Hetzner volume count does not increase.

### 2. Cordon drill

Submit the canary with `pause_before_read=true`. After the writer succeeds:

1. record the bound worker and PVC/PV;
2. cordon that exact worker;
3. resume the suspended workflow;
4. verify the reader stays Pending and the Pending alert expression returns it;
5. terminate the canary, uncordon the worker, and verify PVC/PV cleanup;
6. run the normal canary again.

Never drain the worker for this drill. Cordon is enough to prove the
node-affinity failure mode without evicting unrelated workloads.

### 3. Reconcile canary

In a separate PR, add `storageClassName: argo-workdir-local` only to
`mctl-agents-reconcile`. Observe two scheduled cycles. Accept only if both
succeed, PVC/PV cleanup completes, root disk stays below 70%, quota stays below
80%, and Hetzner volume count does not increase.

### 4. Remaining agent workflows

In a separate PR, switch:

- `mctl-agents-implement`
- `mctl-agents-investigate`
- `mctl-agents-issue-poll`
- `mctl-agents-run`
- `mctl-agents-shepherd`

Observe at least one scheduled execution of every enabled CronWorkflow and
repeat the storage, disk, quota, cleanup, and Hetzner checks.

### 5. Full labs flow

Submit `smoke-test` in namespace `argo-workflows` with:

- `team_name=labs`
- `component_name=local-workdir-smoke-web`
- `component_type=base-service`
- `dockerfile_repo=mctlhq/spring-test`
- `git_tag` pinned to a commit SHA
- `provision_database_on_onboard=true`

The flow must verify that database provisioning finishes before the service
manifest commit, no pod observes a missing referenced Secret, deploy and
update-config complete, and retire removes the service GitOps resources,
workload, app ExternalSecrets, app Secrets, and Vault app secret. The physical
database remains by policy.

## Rollback

Rollback each template by removing only
`storageClassName: argo-workdir-local`; new workflows return to the default
`hcloud-volumes` class. Existing local workflows must finish or be terminated
before removing the provisioner. Do not delete the StorageClass or provisioner
while local PVCs/PVs exist.
