# Spike 2929: web contract preview assurance

STATUS: DOCUMENT_ONLY. Evidence report and decision memo for the preview
harness in `assurance/web-contracts/`. Licenses no consumer change, no CSP,
Cloudflare or CDN change, no SRI enforcement and no production test. Not a
claim of production conformance and not an automatic GO for any consumer
rollout (separate G2/G3 issues).

Issue: mctlhq/mctl-gitops#2929 (re-file of #2544). Parent:
mctlhq/.github#330. Contracts: mctl-design `docs/contracts/web-header-a11y.md`
(1.0.0) and `docs/contracts/web-asset-integrity.md` (gates G1-G4, no version
stated in the document), both read at mctl-design commit
`6d82a6b239365213d6859f2794c2449af7dd4e1f`.

## 0. Labels

- `OBSERVED_CI`: a result of a dated CI run of `web-contract-assurance.yml`
  against pinned inputs, with the run id given. Preview only.
- `VERIFIED_SOURCE`: Git source at a pinned commit or tag.
- `NOT_RUN`: no run produced a verdict. It never means "compliant" and never
  means "absent". Each row says why.

No row below is production evidence. The harness runs consumer images on an

## 1. What exists

A Playwright 1.64.1 harness (`@axe-core/playwright` 4.14.0, pinned image
digest in `pins.json`) with:

- 424 catalogued cases in `cases.json` (generated by `report/gen_cases.py`,
  checked in CI): 148 fixture and isolation cases, and 39 header cases for each
  of `mctl-web`, `mctl-docs`, `mctl-academy`, 53 each for `mctl-telegram`,
  `mctl-alice` and `seerrsense`.
- A fail-closed report (`report/build_report.py`). It iterates over the
  catalogue, never over JUnit, so a case nobody ran is `NOT-RUN`, never `PASS`.
  Eight negative controls (broken fixtures: bad SHA, broken Escape, lost focus
  and so on) must FAIL or the run exits 2 ("scaffolding cannot detect
  failure").
- A request guard: allowlist of fixture and consumer hosts, sensitive-path
  refusal (OAuth, callback, consent and similar), no outbound network. Every
  unexpected block fails the test; a declared block (section 5) is still aborted.
- A CI job on PRs touching those paths and on demand: read-only token, no
  secrets, 7-day artifact. It is an advisory check, not a required one.

Built through #2943 (workflow), #2946 (`mctl-web` image mode), #2947 (HTML
capture), #2949 (pinned design sheets served locally), #2951 (scope decisions),
#2952 (HDR-15 detector), #2954 (declared blocks, HDR-2 scope), #2958 (verdict
split, HDR-13) and #2948 (`mctl-web` breakpoint and selectors), plus the earlier
harness PRs of this issue.

## 3. Findings about the consumer

Both are evidence about `mctl-web` at tag `7.24.0` in a preview run, not a
production claim. The harness is sound for them (positive controls on the
reference fixtures PASS, negative controls FAIL).

1. HDR-16 FAIL (B-1 and 375, no JavaScript): the burger toggle is visible but
   the six primary links are not reachable through it. Owner decision
   (2026-11-23): the FAIL stands and is recorded here; no consumer issue is
   opened now. OBSERVED_CI.
2. HDR-12 FAIL (B-1 and 375): after a link inside the open panel is activated,
   focus is on `body`, not on the toggle or the navigation target. The pinned
   source closes the menu from a click handler (`closeMenu()`) with no focus
   return; that cause is from reading the source earlier in this issue and was
   not re-derived for this document. For in-page anchor links
   "the navigation target" is ambiguous in the contract. OBSERVED_CI for the
   behaviour.

## 5. Scope decisions (owner, 2026-11-23)

- HDR-1 checks the header region only, not every landmark on the page.
- HDR-14 uses header links, and the route step runs only for sites that
  declare `selectors.routes`.
- HDR-8 and HDR-12 (and HDR-13 on narrow viewports) give a panel link focus
  directly; visibility of the indicator does not depend on DOM order, which
  HDR-7 owns. The toggle's own indicator is still checked after a real Tab.
- HDR-15 measures the effective transition (property not `none` and duration
  plus delay above zero) on the navigation and the toggle `::before` and
  `::after` only, matching the contract's own reduced-motion block.
- Hosts a consumer page calls that the isolated run does not allow are declared
  per site in `pins.json` `expected_blocked` as exact `host/path` strings.
  They are still aborted and never answered, counted per case, and shown in the
  matrix. Undeclared blocks still fail. For `mctl-web`: an analytics script, a
  bot-check script and a signup-status call.
- Verdict split: a FAIL on a consumer case is a finding (exit 0, no compliance
  claim, one workflow warning per finding). A fixture or harness FAIL, a
  control that does not FAIL, rejected pins or a guard accounting error make
  the job red.

## 6. What the results do not show

- **Fonts were not loaded.** Font hosts are answered with an empty stylesheet,
  so a layout result that depends on font metrics is not evidence.
- **The declared hosts never ran.** The three scripts and calls above were
  aborted, so any behaviour that depends on them was not exercised. This is
  why those PASS rows are not a compliance claim.
- **Design sheets are not fetched from the real CDN.** `ui.mctl.ai/<version>/<sheet>.css`
  is answered from the pinned mctl-design bytes with a serve-time SHA-256
  check. The run therefore says nothing about live CDN delivery, headers, TTL,
  CORS or SRI behaviour of the real host. `OBSERVED_CI` for the pinned bytes
  only.
- **No asset-integrity gate is run against a consumer.** The G1-G4 cases run on
  fixtures and on the pinned design bytes. Every catalogued `mctl-web` case is a
  header case. Browser SRI and CORS behaviour on a real consumer page is
  `NOT_RUN`.
- **Breakpoints and selectors are observed, not contractual.** `mctl-web`'s
  breakpoint (981) and selectors come from the consumer source at `7.24.0`;
  the contract does not state them. Both are recorded in `pins.json` with
  provenance notes.
- **Consumer images are amd64 only**, so they run in CI, not on an arm64
  workstation.
- **Preview only.** No production host, backend, OAuth, cookie or session was
  contacted.

## 7. Reproduce

```sh
# unit tests of the fail-closed report (no browser, no network)
python3 tests/test_web_contract_report.py

# pins, including the pinned mctl-design commit and its sheet hashes
python3 assurance/web-contracts/report/build_report.py --check-pins --design-repo /path/to/mctl-design

# fixtures-only run locally (Docker): copy pins.json with every site set to not-run
WCA_PINS=/path/to/pins-fixtures-only.json WCA_DESIGN_REPO=/path/to/mctl-design assurance/web-contracts/run.sh
```

A consumer run happens in CI (`web-contract-assurance.yml`, also
`workflow_dispatch`). The artifact `web-contract-assurance` holds
`matrix.md`, `results.json`, `junit.xml`, the guard log and the substitution
record. The local fixtures-only run last gave 136 passed and the 8 expected
negative-control failures, no harness failures.

## 8. Decision memo

Proven, in preview: the harness distinguishes pass from fail (every control
behaves), keeps NOT-RUN distinct from PASS end to end, refuses to touch
sensitive paths or any host outside its allowlist, and produces a reproducible
per-case matrix with pinned source and image. For `mctl-web`, 29 of 39 header
cases have a verdict on the pinned image, two real findings (HDR-12, HDR-16).

Unknown: the other five consumers (not run), live CDN and SRI behaviour,
anything that depends on the three declared hosts or on web fonts, and the
checkbox-header equivalents (HDR-4, HDR-11).

Readiness: the harness is ready to be pointed at more consumers one at a time.
No consumer is ready for a G2/G3 rollout on this evidence: `mctl-web` has two
open FAILs and a gap, and five sites have nothing. Rollout decisions stay
separate issues.
