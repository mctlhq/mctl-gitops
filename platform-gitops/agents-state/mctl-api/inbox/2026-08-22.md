### 1. pgx-critical-memory-safety-cve: Upgrade pgx/v5 to 5.9.2 for critical memory-safety + SQL injection CVEs
**Category:** security
**Impact:** 5
**Effort:** 2
**Rationale:** CVE-2026-33815/CVE-2026-33816 are CVSS 9.8 critical memory-safety flaws affecting all pgx/v5 versions before 5.9.0, and CVE-2026-41889 is a related SQL-injection issue fixed only in 5.9.2; we run 5.8, squarely in the affected range, on our sole Postgres driver serving identities and audit logs. A proposal covering the first two CVEs already exists at `proposals/pgx-upgrade-v592` from a prior cycle but shows no `.status.yaml` (unmerged) — this finding confirms the fix is still outstanding and should be escalated/merged, with CVE-2026-41889 added to its scope, rather than re-drafted as a brand-new proposal. mctl-api runs only in the `admins` tenant, so there is no `labs` resource-usage impact from this dependency bump.
**Source:** https://github.com/advisories/GHSA-9jj7-4m8r-rfcm, https://github.com/advisories/GHSA-xgrm-4fwx-7qm8, https://github.com/advisories/GHSA-j88v-2chj-qfwx

### 2. go-1.24-eol-unpatched-cve: Escalate Go 1.24 EOL — CVE-2026-42507 has no backport path
**Category:** security
**Impact:** 4
**Effort:** 3
**Rationale:** Go 1.24 is now formally end-of-life (only 1.25 and 1.26 receive patches, with 1.27.0 already shipped), and CVE-2026-42507 (net/textproto error-injection) is fixed only in 1.25.11/1.26.4 — it will never be backported to 1.24, so mctl-api's toolchain is now permanently exposed to this and any future stdlib CVE until upgraded. This exact upgrade has already been proposed multiple times (`go-runtime-upgrade`, `go-runtime-upgrade-v2`, `go-upgrade-1262`, `go-upgrade-stdlib-cves`/`-v2`, `go-toolchain-ace-cve-27140`) with none showing a merged status — flagging this as an overdue, escalating item that needs to actually land rather than another parallel draft. No `labs` impact — mctl-api is `admins`-tenant only.
**Source:** https://pkg.go.dev/vuln/GO-2026-5039, https://go.dev/doc/devel/release

### 3. argocd-token-scope-cve-2026-42880: Re-verify ARGOCD_TOKEN scope against new secret-disclosure CVE-2026-42880
**Category:** security
**Impact:** 3
**Effort:** 1
**Rationale:** CVE-2026-42880 (CVSS 9.6) is a newly disclosed, critical ArgoCD flaw letting any authenticated read-only application user extract unmasked Kubernetes Secrets via the grpc-web ServerSideDiff endpoint — distinct from both existing ArgoCD proposals (`argocd-token-scope-audit` for CVE-2025-55190, `argocd-ghsa-3v3m-patch` for GHSA-3v3m-wc6v-x4x3). Patching the ArgoCD server itself is infra-owned and out of scope per `architecture.md`, but confirming the mctl-api-owned `ARGOCD_TOKEN` is minimally scoped and cannot reach the vulnerable dry-run/ServerSideDiff path is a legitimate, narrowly-scoped mctl-api action — especially since the earlier token-scope remediation appears not yet merged either. No `labs` impact — the token is `admins`-tenant scoped and mctl-api does not run in `labs`.
**Source:** https://securityonline.info/argo-cd-critical-secret-leak-cve-2026-42880-kubernetes-security/
