### 1. xnet-idna-punycode-cve: Confirm and patch golang.org/x/net IDNA punycode bypass (CVE-2026-39821, CVSS 9.6) across mctl-api's TLS-facing dependency chain
**Category:** security
**Impact:** 4
**Effort:** 3
**Rationale:** this is the highest CVSS score (9.6) of anything surfaced this cycle. mctl-api makes numerous outbound HTTPS calls that are hostname-driven — Dex JWKS fetch, GitHub API calls, Vault, ArgoCD, Backstage, Argo Workflows (all listed under "External integrations") — via client-go/go-oidc/net-http stacks that commonly vendor `golang.org/x/net`; an IDNA/punycode bypass in that path could enable domain-spoofing against exactly the OIDC/JWKS hostname validation that architecture.md's auth flow depends on. The researcher explicitly flagged applicability as "not confirmed this pass," so effort here starts with a dependency-graph confirmation (does mctl-api's build actually pull an affected x/net version via client-go 0.32 / go-oidc / chi?) before committing to the upgrade path (Go stdlib 1.26.6+ or x/net v0.55.0+); the severity justifies opening the proposal now rather than waiting for a future cycle to re-confirm.
**Source:** CVE-2026-39821, https://github.com/kubernetes/kubernetes/issues/142326 (inbox "Source: cve" section, 2026-09-26).
