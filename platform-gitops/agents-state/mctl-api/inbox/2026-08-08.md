## Top-3 (for spec-writer)

### 1. prometheus-metrics-panic-fix: Bump prometheus/client_golang 1.23 → 1.24.1 (promhttp nil-URL panic fix)
**Category:** security
**Impact:** 4
**Effort:** 1
**Rationale:** This is a confirmed bugfix release that closes a panic in the `promhttp` handler triggered by requests with a nil URL — and mctl-api exposes `/metrics` directly via `prometheus/client_golang`, so this is a crash/DoS vector on a live endpoint, not a theoretical one. It is a same-tenant (`admins`), same-library, low-risk patch bump with no architectural change, so effort and blast radius are both minimal.
**Source:** github releases — prometheus/client_golang v1.24.1, https://github.com/prometheus/client_golang/releases/latest

### 2. mcp-go-upgrade-0-57: Upgrade mark3labs/mcp-go from 0.31 to 0.57.0
**Category:** refactor
**Impact:** 5
**Effort:** 4
**Rationale:** mcp-go is the library our entire MCP server (24 tools, Streamable HTTP) is built on per ADR 0001, and the version gap (0.31 → 0.57) has accumulated real correctness fixes relevant to us — atomic client-init state, SSE multi-line data, session-closure and embedded-resource handling, plus new Streamable HTTP stream-resumability support. ADR 0001 only forbids *downgrading* this library or replacing it with a custom/gRPC implementation, so an upgrade is fully in line with the accepted decision; effort is rated higher because ADR 0001 requires re-validating all 24 tools through the MCP Inspector after any bump, and the 0.31→0.57 jump likely carries breaking changes.
**Source:** github releases — mark3labs/mcp-go v0.57.0, https://github.com/mark3labs/mcp-go/releases/latest

### 3. go-oidc-hardening: Upgrade coreos/go-oidc to v3.20.0 (JWKS + issuer-mismatch hardening)
**Category:** security
**Impact:** 3
**Effort:** 2
**Rationale:** go-oidc underpins the Dex JWT leg of our 3-bearer-type auth flow, and architecture.md explicitly calls out that "a bug here = cross-tenant leak" as a known limitation — this release adds a new API for detecting issuer URL mismatches (directly relevant to token-confusion risks) and makes JWKS handling with unknown signing algorithms fail gracefully instead of hard-erroring. No CVE is attached, so this is a hardening/robustness upgrade rather than an emergency patch, keeping effort moderate.
**Source:** github releases — coreos/go-oidc v3.20.0, https://github.com/coreos/go-oidc/releases/latest

None of the above have any resource-usage implications for tenant `labs` — mctl-api runs exclusively in tenant `admins`, and all three are dependency-version bumps within the existing stack (no new services, no cross-tenant components). No risk flag needed for `labs`.
