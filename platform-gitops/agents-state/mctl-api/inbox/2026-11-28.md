## Top-3 (for spec-writer)

### 1. go-1-26-11-toolchain-xnet: Move build toolchain to Go 1.26.11+ and bump golang.org/x/net >= 0.63.0
**Category:** security
**Impact:** 5
**Effort:** 2
**Rationale:** We are on Go 1.24 (unsupported) and the public API/MCP endpoint is exposed to the net/http HTTP/2 and HTTP/1 advisories, which are fixed only in 1.26.9+ / 1.26.11. Existing Go proposals target older patch levels; this one pins the current fixed level and includes x/net and a govulncheck gate. No extra memory for `labs` expected, but verify the new runtime's footprint there.
**Source:** go1.26.11 release; GO-2026-6603/6859; CVE-2026-97054.

### 2. mcp-go-1-6-allowed-hosts: Adopt mcp-go 1.6.0 and configure WithAllowedHosts for the MCP endpoint
**Category:** security
**Impact:** 4
**Effort:** 2
**Rationale:** Distinct from earlier mcp-go upgrade proposals: this focuses on the 1.6.0-specific DNS-rebinding protection and duplicate request-ID rejection, with an explicit host allowlist (api.mctl.ai). Per ADR 0001, all 24 tools are re-validated via MCP Inspector.
**Source:** mcp-go v1.6.0 release notes.

### 3. govulncheck-ci-gate: Add govulncheck to CI and image build as a release gate
**Category:** refactor
**Impact:** 3
**Effort:** 1
**Rationale:** Repeated stdlib and dependency CVE proposals indicate drift is detected late, manually. A reachable-vuln gate catches it at PR time with negligible runtime cost.
**Source:** pattern across Go advisories above.
