## Tests
- [ ] T1. One eligible team, unselected: the consent page has no `checked` option; posting approve without `tenant` -> `access_denied`, no grant row, no code.
- [ ] T2. Multiple eligible teams: only membership ∩ allowlist teams are listed; posting a listed team issues a grant for exactly that team; posting a non-listed, foreign or repeated `tenant` -> refused, no grant.
- [ ] T3. Same team, two users: user A's grant cannot be used by B's token (principal mismatch -> `ambiguous_tenant`); A's allowlist row does not admit B (`not_in_pilot`).
- [ ] T4. Forged inputs: an `X-Mctl-Selected-Tenant` header, `?tenant=` query, `tenant`/`owner`/`namespace`/`task_queue` in the body or MCP args, and `tenant` on `/oauth/authorize` or `/oauth/token` never change the resolved scope and are refused where the contract says so. A hand-crafted JWT with `stn` but an unknown `tgr` -> `ambiguous_tenant`. `tgr`/`stn` on an API-audience token -> ignored.
- [ ] T5. Wrong audience and multi-aud: an API or support token on a Glovo route -> `not_authorized`/401; a Glovo token whose `aud` holds two entries -> rejected at verification.
- [ ] T6. Membership removed mid-session: the next resource request -> `no_tenant`; the next refresh -> `invalid_grant`, with grant and family revoked. Allowlist row removed -> `not_in_pilot` on the next request.
- [ ] T7. Refresh switching team: a team parameter on the token endpoint -> `invalid_request`; a new authorize+consent for team B supersedes team A's grant, and A's still-valid access token then fails `Check` -> `ambiguous_tenant`.
- [ ] T8. Personal scope and no `labs` default: a principal whose only membership is `admins` sees no eligible team; a team member in `labs` who is individually allowlisted **may select it explicitly**, never by default; a grant naming a non-selectable or non-team tenant -> `scope_unsupported`; nothing ever resolves to `labs` by default.
- [ ] T9. Expired, revoked and pending grants -> `ambiguous_tenant` (a `pending` grant fails `Check`, `CheckTx` and `Resolve`; only `ActivateTx` can activate it, and it refuses an expired one); a grant/membership/allowlist store failure -> 503, and a failure on refresh spends no token.
- [ ] T10. No Telegram/surface fallback: a relayed surface identity, an agent-run token and an admin without an allowlist row all fail `Resolve`.
- [ ] T11. Revocation: RFC 7009 revoke and `RevokePrincipalSessions` revoke the grant before the family; a grant-store failure is 503, not success.
- [ ] T13. Consent-token replay: posting the same consent `token` twice yields at most one grant and one code; the second post is `access_denied` and writes nothing.
- [ ] T14. Auth-code reuse: exchanging the same Glovo code twice yields tokens once; the second exchange is `invalid_grant` and activates nothing.
- [ ] T15. Kill switch: with `GLOVO_ENABLED` unset and `GLOVO_MCP_RESOURCE` set, `/oauth/authorize` with the Glovo resource is refused `invalid_target`/not ready and `glovo.Gate` refuses `not_ready`; with it on but any readiness dependency missing, the same.
- [ ] T16. Atomicity: fault injection after the refresh insert and before grant activation, after activation and before commit, and during revocation leaves no active grant without a live family, no live family bound to a revoked or pending grant, and no signed access token.
- [ ] T17. Pending-grant semantics (round 3): exchanging a valid Glovo code succeeds with no separate `Check` (the grant is `pending` until `ActivateTx`); a `pending` grant, one whose code was lost, and one past `expires_at` all fail `Resolve`; `ActivateTx` on an expired or mismatched (principal, client, resource) grant updates zero rows and the exchange fails `invalid_grant` with no refresh row committed. Mutation: making `Check` accept `pending` turns the `Resolve` case red.
- [ ] T18. Reuse detection (round 3): replaying a rotated Glovo refresh token revokes the family and the team grant in one commit (fault injection between the two statements commits neither); the `tgr`-bearing access token then fails `Resolve`. Eligibility loss at refresh: `accept` refuses, nothing is written inside it, and the post-`RotateIfTx` write revokes grant and family. A `RevokeRefreshToken` grant-store failure surfaces as 503.
- [ ] T12. Regression: with `GLOVO_MCP_RESOURCE` unset, the existing `oauth_*_test.go` suites pass unchanged, and non-CIMD API-audience flows still skip consent.
