## Rollback
The change is additive. Revert the PR and redeploy. The previous image ignores the `tenant` column and the new indexes. Support rows already written stay in `audit_events` and do no harm, because the old `List` would show them, so on a long-lived rollback run `DELETE FROM audit_events WHERE operation = 'support.request'` or let them age out. To drop the schema additions as well: `DROP INDEX CONCURRENTLY IF EXISTS audit_events_support_tenant, audit_events_via_execution; ALTER TABLE audit_events DROP COLUMN IF EXISTS tenant;` (optional). If only the MCP fail-closed refusal misbehaves, a revert is still the path. No feature flag is added, because support runs are new and an unaudited support read is not an acceptable fallback.
