## Tests

Fixtures are synthetic files under `internal/deployanalyze/testdata/<case>/` and are served by a fake
`ContentReader` (and by an `httptest.Server` for the HTTP reader tests). For each detector, run the
test once with the check reverted to confirm it goes red.

- [ ] T1. Converged Tier 0 fixture (`tier0-node`): `EXPOSE 3000`, `USER node`, and `HEALTHCHECK CMD curl -fsS http://localhost:3000/healthz`. The result has `supported: true` and `tier0`, and its `draft_intent` validates against the vendored schema and has `environment: preview`, `exposure.mode: internal` and `replicas: 1`.
- [ ] T2. `TestVendoredSchemaPinned` checks the SHA-256 of the embedded schema against `SchemaSHA256`. `TestVendoredSchemaMatchesSource` compares with `DEPLOY_INTENT_SCHEMA_SOURCE` and is run in CI.
- [ ] T3. Port detector: the converged fixture passes. Mutations: `EXPOSE 80` gives `privileged_port`; `EXPOSE 3000 8080` gives needs_input `runtime.port` with both candidates; no EXPOSE gives needs_input; `EXPOSE ${UNSET}` gives needs_input; `ARG PORT=3000` with `EXPOSE $PORT` resolves to 3000.
- [ ] T4. Health detector: the converged fixture passes. Mutations give needs_input `runtime.healthPath` with no path for `HEALTHCHECK NONE`, no HEALTHCHECK, `curl -X POST`, `curl -d x`, a remote host, a port that differs from the detected port, a query string, and a `CMD /bin/check` script. A `wget -qO- http://127.0.0.1:3000/ready` check passes.
- [ ] T5. User detector: the converged fixture passes. Mutations give `runs_as_root` for no USER, `USER root`, `USER 0`, `USER 0:0`, an unresolved variable, and a USER only in a non-final stage when the final stage is `FROM` an external image. A USER inherited through `FROM builder AS final` is honoured.
- [ ] T6. Compose detector: a single-service compose with no host ports passes. Mutations give `multi_service` (two services), `privileged` (`privileged: true`, `cap_add`, `network_mode: host`), `host_ports` (`"8080:3000"`, long-syntax `published`), `gpu` (`deploy.resources.reservations.devices`, `gpus: all`), and `compose_unparseable` (YAML aliases or a depth bomb).
- [ ] T7. No Dockerfile: the commit resolves and the contents call answers 404, which gives `supported: false` and `no_dockerfile` with HTTP 200. A directory at the path gives `dockerfile_not_a_file`. A size over the cap gives `dockerfile_too_large`.
- [ ] T8. Fail closed on GitHub, using an `httptest` fake. A 500, 502, timeout, 403 rate limit, malformed JSON, a body over the cap, a base64 length that differs from `size`, or missing `content` on the contents or commit call each give 502 `deploy_github_*`, never `Unsupported`. A commit that answers 404 or 422 gives 422 `deploy_revision_unreadable`, even if the contents call would have answered 404.
- [ ] T9. Authorization: a member of tenant B analyzing tenant A gives 403 `deploy_tenant_access_denied` and makes no GitHub call. A repository bound neither in gitops nor in the portal gives 403 `deploy_repository_not_bound` and makes no GitHub call. A repository bound only in the portal is allowed. - [ ] T11. Reverse lookup visibility: with services in tenants `a` and `b` bound to the same repository (mixed case), a member of `a` sees only the `a` rows and an admin sees both. A repository bound to three services returns three rows, sorted.
- [ ] T12. Input validation: a branch name in `revision`, a 39-hex value, an uppercase hex value, `../Dockerfile`, `/Dockerfile`, `owner/..`, and repeated query params each give 400 and one audit row.

## Rollback

Everything is additive and read-only. To roll back, revert the PR, or redeploy the previous mctl-api
image tag. No data, gitops state or GitHub state is written, so nothing needs cleaning up. If only the
MCP surface is problematic, the two tools can be removed in a follow-up while the REST routes stay; the
portal allowlist already has them disabled. If the vendored schema drift check blocks CI unexpectedly,
re-vendor the file from mctl-gitops `main` and update `SchemaSHA256`. Do not disable the check.
