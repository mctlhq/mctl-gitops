## Rollback

All schema changes are additive columns with defaults, so rolling back the
image to the previous release is safe: old code ignores the new columns, and
approvals decided under the new code remain consumable by the old code (it
checks only state, intent hash and `expires_at`). For a softer rollback
without redeploying old code, set `ACTION_APPROVAL_MAX_DECISION_AGE=168h` to
neutralise the freshness bound. Authority and policy revalidation have no
kill switch by design, since they are the fix. If one is needed, revert the
commit for task 5 alone; tasks 2-4 and 7 can stay. No data migration needs
undoing; leaving the columns in place is harmless.
