# Tasks: issue-285-feat-mcp-propagate-otel-span-context-thr

## Owner constraints (approved 2026-10-10) -- binding on every task below

Marked inline on the tasks they change. A PR that breaks one of these is not done.

- **I1. No endpoint, no export.** With no `OTEL_EXPORTER_OTLP_*` endpoint (or `OTEL_SDK_DISABLED=true`), no exporter exists and every response and behavior is byte-identical to today (T4d, T7).
- **I2. Collector down is invisible to callers.** Request and tool latency do not materially degrade and no application path fails when the Collector is unreachable (T5).
- **I3. No payloads in spans.** No tool arguments, prompts, completions or other private payloads in span attributes or events (T6).
- **I4. Additive, backward-compatible DB changes.** New columns are nullable or defaulted, migrations are idempotent, and old rows read back cleanly (T8).
- **I5. Additive API shape.** Existing response keys and types are unchanged; `trace_id` / `run_id` are only ever added, and omitted when unknown (T4d).
- **I6. Deterministic parent selection.** See task 5 and T2b: the rule for a request carrying both an HTTP `traceparent` and an MCP `_meta.traceparent` is fixed and tested, including when they conflict.
- **I7. Catalog names only.** Attribute names come from the live catalog, `mctl-docs/docs/reference/telemetry-attributes.md` (`mctlhq/mctl-docs#107` in this proposal is a wrong reference). No parallel names. See task 11 for the mapping.

## Tests

- [ ] T1. Propagation over the HTTP header: POST `tools/call` to `/mcp` with `traceparent: 00-<T>-<S>-01`, using `tracetest.NewInMemoryExporter`. Assert that all spans recorded for the call (HTTP server, tool, loopback client, REST server, operation) have trace id `<T>` and that the root of the recorded subtree has parent `<S>`.
- [ ] T2. Propagation through MCP `_meta`: the same as T1 with `params._meta.traceparent` and a different HTTP header. Assert that the tool span's parent comes from `_meta`.
- [ ] T2b. **I6 conflict rule.** Send a `tools/call` whose HTTP `traceparent` and `_meta.traceparent` carry *different* valid trace ids. Assert that the tool span's trace id and parent come from `_meta`, that the HTTP server span is linked rather than parented, and that the result is identical over repeated runs. Also cover a valid HTTP header with an invalid `_meta` value (HTTP wins) and both invalid (new root).
- [ ] T3. Malformed or absent `traceparent`: the request succeeds, and a new root trace id is generated and returned by execute.
- [ ] T4. Trace id round trip: (a) execute, then `GetWorkflow` returns the same `trace_id`; (b) create an incident, then `GetIncident` returns `trace_id`; (c) a fake Temporal client with a memo makes `GetDevLoopWorkflow` return `trace_id` and `run_id`; (d) rows or memos without a trace id produce responses whose key set equals today's (golden JSON comparison for shape stability).
- [ ] T5. Collector unavailable: configure `OTEL_EXPORTER_OTLP_ENDPOINT` to a blackholed address (a listener that accepts and never responds). Run 200 tool calls and assert that p99 latency is within a small margin of the export-disabled baseline, that every response is unchanged, and that `trace_id` is still returned.
- [ ] T6. Privacy: call `mctl_deploy_service`, `mctl_get_incident`, `mctl_save_openclaw_skill` and `mctl_trigger_issue` with sentinel strings in every argument and a sentinel bearer token. Assert that no span attribute key falls outside the `attrs.go` allowlist and that no attribute or event value contains a sentinel.
- [ ] T7. Disabled mode: with `OTEL_SDK_DISABLED=true`, no exporter is created, the Argo annotation and Temporal memo are still set from an incoming `traceparent`, and all existing tests pass.
- [ ] T8. Migration idempotency: run the `audit` and `alerts` schemas twice against a test database (existing pattern in the store tests). Pre-existing rows read back with an empty `TraceID`.
- [ ] T9. Run `go test ./...`, `golangci-lint run` and the `e2e` suite (`cd e2e && go test -v`). The tool count is unchanged.

## Rollback

- Runtime kill switch with no deploy: set `OTEL_SDK_DISABLED=true` (or unset `OTEL_EXPORTER_OTLP_ENDPOINT`) in the `mctl-gitops` values. Export stops immediately on pod restart. Propagation and stored ids keep working, and responses are unaffected.
- Code rollback: revert the PR and redeploy the previous image tag (`mctl_rollback_service`). The new `trace_id` columns are additive with a default and are ignored by the old code, so no down-migration is needed. If necessary they can be dropped later with `ALTER TABLE ... DROP COLUMN trace_id` once nothing reads them.
- Argo annotations and Temporal memos already written are inert metadata, and the old code ignores them.
