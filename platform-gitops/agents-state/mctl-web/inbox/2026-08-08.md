## Source: cve

- **CVE-2026-71315 — Nuxt route rules silently dropped for mixed-case paths (incomplete fix for CVE-2026-53721)** — `routeRules` lookups are case-folded while the stored key stays mixed-case, so rules like `/Admin` or `/Dashboard/**` never match when `router.options.sensitive` is false; most serious impact is an appMiddleware auth-gate being silently dropped. Affects 3.21.7–<3.21.10 and 4.4.7–<4.5.1; fixed in 3.21.10 / 4.5.1. mctl-web's architecture doc pins Nuxt 4.3.1, which is below the affected range floor (4.4.7) but was already flagged last cycle for the earlier related CVEs. [GitLab Advisory DB](https://advisories.gitlab.com/npm/nuxt/CVE-2026-71315/)

- **CVE-2026-71321 — Nuxt unauthenticated CPU exhaustion via island endpoint** — `/__nuxt_island/...` decodes and hashes attacker-controlled request bodies before validating the URL-resident hash; large JSON bodies are fully processed before rejection, so a low request rate can degrade or stall the server without authentication or a valid hash. [GitLab Advisory DB](https://advisories.gitlab.com/npm/nuxt/CVE-2026-71321/)

- **CVE-2026-71320 — Nuxt server-side RCE via runtime template injection in server island props** — Nuxt server islands accept props via the `/__nuxt_island/` endpoint; exploitable when `vue.runtimeCompiler: true` is enabled. [GitLab Advisory DB](https://advisories.gitlab.com/npm/nuxt/CVE-2026-71320/)

- **CVE-2026-71319 — Nuxt DevTools critical unauthenticated RCE via RPC** — Critical (CVSS 9.6) RCE in Nuxt DevTools prior to v3.3.1 via unauthenticated RPC calls. [TheHackerWire](https://www.thehackerwire.com/nuxt-devtools-critical-rce-via-unauthenticated-rpc/), [Hacktron AI changelog](https://www.hacktron.ai/security-changelog/nuxt)

- **Server island v-for prop — unbounded SSR memory allocation / crash** — Search results (via search summary, not a dedicated CVE ID found) describe an unauthenticated attacker using a server island `v-for` prop to trigger unbounded SSR memory allocation and crash the Nuxt process; fixed alongside CVE-2026-71315 in 3.21.10 / 4.5.1. ## Top-3 (for spec-writer)

### 1. nuxt-4-5-1-security-patch: Upgrade Nuxt off 4.3.1 to close island-endpoint DoS and route-rule bypass CVEs
**Category:** security
**Impact:** 5
**Effort:** 3
**Rationale:** CVE-2026-71321 is an unauthenticated CPU-exhaustion DoS on the `/__nuxt_island/` endpoint that ships with any SSR=true Nuxt app such as mctl-web (SSR=true per `context/architecture.md`), and it is fixed in 4.5.1 alongside an unconfirmed but plausibly related "unbounded SSR memory via server island `v-for` prop" crash bug. mctl-web's pinned 4.3.1 sits below the entire 4.4.x/4.5.0 vulnerable window described for the companion CVE-2026-71315 (route-rules case-folding auth-gate bypass, floor 4.4.7), so that specific bypass does not apply today, but staying two minor lines behind the current patched release on a public-facing service is itself the risk worth closing proactively. CVE-2026-71320 (island prop RCE) is intentionally excluded — it only triggers when `vue.runtimeCompiler: true`, which mctl-web does not set. This does not touch tenant `labs` (mctl-web runs in `admins`) and does not conflict with ADR 0001 (framework stays Nuxt/Vue).
**Source:** CVE-2026-71321, CVE-2026-71315 (GitLab Advisory DB); nuxt/nuxt v4.5.2 release notes — inbox 2026-08-08.

### 2. wrangler-commit-hash-injection: Patch Wrangler OS command injection in the Worker deploy pipeline
**Category:** security
**Impact:** 5
**Effort:** 2
**Rationale:** mctl-web is the only service whose build pipeline (`deploy.yml`) lives in-repo and deploys the Cloudflare Worker via Wrangler in GitHub Actions; GHSA-36p8-mvp6-cv38 shows `wrangler pages deploy --commit-hash` passes that value unsanitized to a shell, enabling arbitrary command execution in CI with access to every Worker secret (`GITHUB_CLIENT_SECRET`, `GITHUB_OAUTH_HMAC_KEY`, `BACKSTAGE_LANDING_TOKEN`, `TELEGRAM_BOT_TOKEN`, `RESEND_API_KEY`). Bumping the pinned wrangler version to the current 4.120.0 and auditing how `--commit-hash` is sourced in the workflow directly closes this before it's exploited; effort is low since it is a CI dependency/config change, not an application change, and does not conflict with ADR 0001's "keep the Worker" constraint (it strengthens it).
**Source:** GHSA-36p8-mvp6-cv38 (cloudflare/workers-sdk security advisories); wrangler@4.120.0 release notes — inbox 2026-08-08.

### 3. admins-resource-headroom: Investigate rising CPU/memory usage trend in tenant admins
**Category:** performance
**Impact:** 4
**Effort:** 3
**Rationale:** `mctl_get_service_status` metrics for tenant `admins` (where mctl-web actually runs) show CPU-limit utilization climbing 75%→85% and memory-limit utilization climbing 72%→82.5% over the last three weekly readings (2026-07-18 → 2026-08-08); at this rate `admins` risks throttling or OOM before the next cycle. This is unrelated to `labs`'s known memory-limit pressure — mctl-web does not run in `labs`, so this proposal carries no risk to that tenant — but it is a genuine capacity risk for mctl-web's own home tenant and is worth a proposal to profile the Nuxt build output / Worker memory footprint and identify what's driving the trend before requesting a blind quota increase.
**Source:** mctl metrics (`mctl_get_service_status`, tenant admins), 2026-07-18 vs 2026-08-08 readings — inbox 2026-08-08.
