## Top-3 (for spec-writer)

### 1. nuxt-security-upgrade-4-7: Upgrade Nuxt to patched release (>=4.6.4, target 4.7.x)
**Category:** security
**Impact:** 5
**Effort:** 2
**Rationale:** Several medium CVEs (route-rule/auth bypass via encoded slashes, dev-server secret/file exposure) affect the recorded version 4.6.2 (or older 4.3.1). Upgrade is a minor bump with a documented command. Public site with SSR makes this the top security item.
**Source:** CVE-2026-128071, CVE-2026-119200, CVE-2026-119201, Nuxt 4.7.0 release notes.

### 2. wrangler-4-169-upgrade-oidc-eval: Bump wrangler/workerd and evaluate OIDC tokens binding
**Category:** security
**Impact:** 3
**Effort:** 2
**Rationale:** The Worker holds many long-lived secrets (Telegram, GitHub, Backstage, Resend). Bumping wrangler keeps the runtime current; evaluating `oidc_tokens` could reduce secret sprawl, e.g. for the Backstage call. Not a replacement of the Worker, so consistent with ADR 0001.
**Source:** wrangler 4.169.0 release.

### 3. nuxt-runtime-config-validation: Validate runtime config at startup and remove the placeholder apiSecret
**Category:** refactor
**Impact:** 2
**Effort:** 2
**Rationale:** Nuxt 4.7 supports Standard Schema validation of runtimeConfig, and `runtimeConfig.apiSecret = '123'` is a known placeholder. yup already ships Standard Schema support, so no new library, keeping within ADR 0001 (no replacement of yup). Fails fast on misconfiguration. Depends on proposal 1.
**Source:** Nuxt 4.7.0 release; context/architecture.md known limitations.
