## Top-3 (for spec-writer)

Caveats: the CVE details come from a single source (OpenCVE search) and are unverified; spec-writer should confirm against the official Nuxt GitHub advisories before citing them. Version data in context is inconsistent: architecture.md and ADR 0001 say Nuxt 4.3.1, while current-version.md says 4.6.2 (the service version, or possibly Nuxt). The real version must be confirmed from `package.json`/lockfile. No finding touches tenant `labs`. The Nuxt work affects the build step and the `admins` tenant only, and no runtime memory increase is expected.

### 1. nuxt-4-6-4-security-upgrade: Upgrade Nuxt to 4.6.4 (nitropack 2.13.6)
**Category:** security
**Impact:** 4
**Effort:** 2
**Rationale:** The 4.6.4 release reportedly fixes about eight Nuxt advisories and three Nitro advisories, including a `//` path bypass, a `%2F` routeRules issue, a ReDoS in `_payload.json` and error-detail leakage. Several of these are rated Medium, and the one affecting all 3.x–4.6.x versions applies regardless of which baseline is correct. Staying on the current version means shipping known-vulnerable code. This is a minor-level bump inside Nuxt 4, so it is consistent with ADR 0001, which only requires tracking Nuxt releases. The spec should cover the behaviour changes (stripped production error details, dev-server Host checks) and note that the `/_nuxt/@fs/` issue is dev-only.
**Source:** nuxt v4.6.4 release; CVE-2026-128077, -128071, -128074, -128075 (single-source, unverified).

### 2. nuxt-path-confusion-regression-tests: CI smoke tests for path normalization and routing exposure
**Category:** security
**Impact:** 3
**Effort:** 2
**Rationale:** The recurring theme in this month's advisories is path confusion (`//`, `%2F`, `/%2e/`) bypassing checks keyed to a literal path. The site is mostly prerendered and has no `admin.vue`, so exposure is probably low. Even so, a small post-build test that requests such paths against `/`, `/docs`, `/privacy` and `/api/*` is cheap. It should also verify that the Worker's rate-limit and route matching on `mctl.ai/api/*` behave the same for encoded and double-slash variants, and that production error responses no longer leak details. The test would run in the existing `deploy.yml` before deploy.
**Source:** CVE-2026-128077, CVE-2026-128071, CVE-2026-119200 (single-source, unverified); nuxt 4.6.4 behaviour changes.

### 3. worker-toolchain-bump-compat-date: Bump wrangler/workerd toolchain and review the Worker compatibility_date
**Category:** refactor
**Impact:** 2
**Effort:** 2
**Rationale:** workers-sdk and workerd both shipped on 13 Nov, and the default compat date moved to 2026-11-13. The Worker handles OAuth, the Backstage token and the Telegram and Resend secrets, so keeping the runtime and tooling current is cheap hygiene. The spec should pin the toolchain, evaluate the compat-date bump against the OAuth, submit and contact flows in staging, and avoid adopting the autogated MemoryCache. No advisories were found, so this is lower priority than items 1 and 2.
**Source:** workers-sdk @cloudflare/workers-auth@0.18.2; workerd v1.20261113.1.
