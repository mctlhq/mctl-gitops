## Top-3 (for spec-writer)

### 1. svgo-billion-laughs-dos: Patch vite-svg-loader/svgo Billion-Laughs XML DoS (CVE-2026-29074)
**Category:** security
**Impact:** 3
**Effort:** 1
**Rationale:** We pin `vite-svg-loader 5.1.1`, which pulls in `svgo` as a transitive dependency; GHSA-xpqw-6gx7-v673 / CVE-2026-29074 is a high-severity XML entity-expansion DoS in svgo's SVG parser. No existing proposal covers this package (it is distinct from the already-open `cloudflare-vite-plugin-cve-fix`, which targets a different package, `@cloudflare/vite-plugin`, for a different CVE). Attack surface is limited to build/dev-time SVG processing rather than runtime user input, so impact is capped at 3 rather than higher, but the fix is a low-effort version bump and is architecturally in scope (vite-svg-loader is an explicitly tracked dependency in `context/architecture.md`).
**Source:** inbox `## Source: cve` — "vite-svg-loader → svgo transitive dependency ... CVE-2026-29074" — https://github.com/jpkleemans/vite-svg-loader/issues/167

### 2. mctl-ru-host-drift: Investigate live host mctl.ru vs. documented primary host mctl.ai
**Category:** security
**Impact:** 4
**Effort:** 2
**Rationale:** `mctl_get_service_config` reports the live host as `mctl.ru`, but `context/architecture.md` documents `mctl.ru` as only a redirect-source domain and `mctl.ai` as the primary host serving GitHub OAuth callbacks and Backstage-integrated forms; if production traffic is genuinely being served from the wrong domain (rather than a stale config-tool label), OAuth callback allow-lists, cookies, and CORS could be silently mismatched. This is a distinct concern from the already-open `reconcile-current-version-doc` proposal, whose scope is explicitly limited to the version-number field and out-of-scope for "any application code, dependency, or infrastructure change" — the host/domain discrepancy needs its own investigation and, if confirmed, a routing/config fix.
**Source:** inbox `## Source: mctl metrics` — "Deployed imageTag discrepancy ... host `mctl.ru`" cross-checked against `context/architecture.md` Cloudflare Worker routes section.

### 3. vite-dev-server-file-read-cve: Verify and patch Vite dev-server file-exposure CVEs bundled via Nuxt
**Category:** security
**Impact:** 3
**Effort:** 2
**Rationale:** CVE-2025-31125 (arbitrary file read) and CVE-2026-53571 (`server.fs.deny` bypass) affect the Vite build tool that Nuxt bundles internally for the dev/build pipeline; this is a different package and different CVE from the already-open `cloudflare-vite-plugin-cve-fix` (which targets `@cloudflare/vite-plugin` directly). The researcher could not confirm which Vite version Nuxt 4.3.1 bundles, so this item starts as a verification spike (check `npm ls vite`) before deciding whether a standalone bump is needed or whether the in-flight `nuxt-security-patch` upgrade already resolves it as a side effect.
