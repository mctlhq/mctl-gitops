# Design: issue-876-feat-scout-generate-structured-spike-dra

## Current state
- `orchestrator/scout/render.py`
  - `draft_body(item: Scored, run_id)` returns six header lines (`Source`, `Question`, `Outcomes`, `Lifecycle: proposed`, `Related` (comma-joined or `none`), `Why mctl`), a blank line, and `Generated by mctl-agents scout, run {run_id}.`
  - `_url(repo, title, body)` builds `https://github.com/mctlhq/{repo}/issues/new?` with `urlencode({"template": "spike.yml", "title", "body", "labels": "spike:scout"})`.
  - `draft_url(item, run_id)` returns `(url, None)` when the URL is no longer than `MAX_BUTTON_URL_CHARS = 2000`. Otherwise it returns a short URL whose body is `Source: {link}` (title cut to 120 characters if needed), together with the full body.
  - `render_digest()` pairs `{"text": f"Draft spike {n}", "url": url}` with `{"text": f"Create spike {n}", "callback_data": f"scout:create:{n}"}` in one row. A comment there notes that mctl-agent `internal/scoutspike` reads the draft back from the URL button in that row. Fallback full bodies become HTML-escaped `Draft {n}:` overflow replies, only for items kept in the message.
- `orchestrator/scout/dedupe.py`: `_SOURCE_RE = r"^Source:\s*(\S+)"` (MULTILINE) extracts the source link from existing `spike:scout` issue bodies. This is the dedupe key.
- `orchestrator/scout/scoring.py`: the scoring schema caps `question` at 240, `outcomes` at 60 and `why_en` at 200 characters, and `related` at 3 items. These maxima bound the header size.
- `tests/test_scout.py`: `_scored()` fixture; `test_draft_url_short_and_long`, `test_overflow_drafts_only_for_kept_items` and `test_each_row_pairs_draft_url_with_create_callback` cover the current contract.
- `docs/operations/scout.md` documents the scout. There is no `.github/ISSUE_TEMPLATE/` in this repo; `spike.yml` is inherited from the org.
- URL budget measurement (Python `urlencode`, 100-character link, all fields at their maxima, 3 related refs, repo `mctl-agents`):
  - The issue's verbatim scaffold is 1,194 characters raw and 1,322 encoded, which would exceed 2000 for most items.
  - A compact scaffold of 671 characters raw (771 encoded) gives a total URL of 1,929 characters.

Deployed state checked:
- `$MCTL_GITOPS_ROOT` `services/` and `tenants/`: a grep for `scout` returned no matches. The scout's CronWorkflow/CWFT lives outside these directories (`docs/operations/scout.md` says it is added on the mctl-gitops side) and was not observed here. This change is code-only, and its deployed behavior depends only on the image.
- The mctl-agent `internal/scoutspike` handler was not observed (it is in a different repo). Its URL-reading behavior is taken from the code comment in `render.py`.

## Proposed solution
1. In `orchestrator/scout/render.py`, add a module constant `SPIKE_SECTIONS: tuple[tuple[str, tuple[str, ...]], ...]`, an ordered list of (heading, bullets) for the six sections, with compact wording:
   - `Existing / duplicate check`: "Verify Related against current issues/code; reuse an existing owner, no parity-only capability."
   - `Required experiment`: "Smallest bounded experiment that can falsify the question, on current MCTL workload, not vendor claims."
   - `Measurements`: "Baseline vs candidate: success, cost, latency, reliability. unknown is not zero."
   - `Invariants`: "No rollout or authority expansion; identity/policy/approval boundaries stay authoritative."
   - `Deliverables`: "Duplicate map, experiment evidence, follow-ups for proven gaps, one recommendation from Outcomes."
   - `Non-goals`: "Implementation before the decision; new epic/runtime for parity only."
   
   Expose `REQUIRED_SECTIONS = tuple(h for h, _ in SPIKE_SECTIONS)` so that tests and docs share the vocabulary.
2. Change `draft_body()` to emit the unchanged six header lines, then `"\n\n## {heading}\n- {bullet}"` for each section, then `"\n\nGenerated by mctl-agents scout, run {run_id}."`. `Source:` stays at byte 0. Header formatting (including `Related: none`) is unchanged.
3. Leave `_url`, `draft_url`, `render_digest`, `MAX_BUTTON_URL_CHARS` and the button/callback construction untouched. The fallback naturally returns the new structured body as `full_body_if_fallback`, and it reaches Telegram through the existing overflow reply.
4. Docs: in `docs/operations/scout.md`, add a "Draft body" subsection listing the header lines and section vocabulary. Note that the org form `spike.yml` should mirror this vocabulary as a manual follow-up, which is not done here.

Why this way: one static scaffold keeps the change local to `draft_body()`, adds no model cost and keeps scout as a renderer, not an investigator. Sizing the prose so that a worst-case-field item still fits the URL means "Create spike" (which reads the URL) yields the structured issue in the common case.

## Alternatives
- Use the issue's verbatim prose. Dropped: the 1,322 encoded characters push most realistic items over 2000, so the URL fallback (`Source:` only) becomes the norm, and both "Draft spike" and "Create spike" would lose the structure.
- Have the scoring model generate item-specific experiment and measurement text. Dropped: it adds token cost and schema fields, makes scout a partial investigator (which the issue rejects) and makes URL size unpredictable.
- Raise `MAX_BUTTON_URL_CHARS`, or make the fallback body `Source:` plus the scaffold without the header. Dropped: the issue says to preserve the fallback behavior, the limit protects Telegram/GitHub URL handling, and changing the fallback body affects the mctl-agent callback contract.

## Platform impact
- No migrations, config or gitops changes. The change takes effect when the next mctl-agents image runs the scout CronWorkflow.
- Backward compatibility: `Source:` is still the first line, so dedupe of existing and new issues is unaffected. Header lines, `Lifecycle: proposed`, the footer line, button texts and the callback are unchanged.
- Resources: each draft URL grows by about 770 characters. The Telegram message text is unaffected, because URLs live in `reply_markup`, which is not counted in the 4096-character `MAX_MESSAGE_CHARS`. The overflow replies for fallback items grow by the same amount and remain capped at 4096 characters.
- Risk: items with very long links (more than about 170 characters at maximum field lengths) now fall back where they did not before. Mitigation: the fallback still delivers the full body through overflow replies, and a test pins the worst-case-field and 100-character-link budget so that future prose growth fails CI.
- Risk: the shortened prose drops nuance from the issue text. Mitigation: all six semantic sections remain, and the reviewer confirms the wording (see Open questions).
