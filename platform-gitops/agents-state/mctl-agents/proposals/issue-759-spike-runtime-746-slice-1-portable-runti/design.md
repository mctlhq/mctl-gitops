# Design: issue-759-spike-runtime-746-slice-1-portable-runti

## Current state
- No `experiments/` directory exists, and no tracked file contains `experiments/`, `mctl-runtime`, `Cargo.toml`, `Cargo.lock` or any `.rs` file (`git ls-files | grep -iE 'cargo|\.rs$|rust'` matches only `config/context-strategies/versions/trust-freshness-ranked/1.0.0.yaml`, a false positive on "trust"; a recursive grep for `experiments|mctl-runtime` found nothing).
- `Dockerfile` copies explicit paths only: `COPY pyproject.toml uv.lock ./` (line 120), `COPY orchestrator/`, `COPY config/`, `COPY agents/` (lines 138-140), `COPY entrypoint.sh` (line 146), plus the pinned `uv` binary (line 117). There is no whole-context `COPY . .`, so an `experiments/` tree would not reach the image today, but nothing enforces that.
- `.dockerignore` excludes `.venv/`, caches, runtime state (`agents/*/inbox/` etc.), `.git/`, `.github/`, `README.md` and editor files. It does not mention `experiments/`.
- `.gitignore` excludes `.venv/`, caches, `.claude/worktrees/`, runtime agent state. No Rust `target/` entry.
- `.github/workflows/pr-validation.yml`:
  - `commit-lint` (line 40 onwards) diffs `BASE...HEAD` with `--no-renames` and at line 134 sets `SHIPPING_PATHS='^(tests/|docs/|\.github/)'`; if every changed path matches, it echoes "Every changed path is under tests/, docs/ or .github/ — this PR ships nothing" (line 136) and exits 0; otherwise it requires a commit subject matching `^(feat|fix|perf|revert)(\([^)]+\))?!?: `.
  - `tests` runs `uv run --locked pytest -q` with `MCTL_GITOPS_ROOT` pointing at an mctl-gitops checkout placed at `./_gitops` inside the workspace (lines 220-230). Any repo-wide filesystem walk in a test must therefore prune `_gitops/`.
  - `lint` runs `uv run --locked ruff check orchestrator config tests tools` and `mypy` (whose `[tool.mypy]` files in `pyproject.toml` deliberately exclude `tests/`).
  - `docker-build` builds the image with `docker/build-push-action` and import-smoke-tests the entrypoints.
  - Pinned action SHAs used: `actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1`; top-level `permissions: contents: read`.
- `pyproject.toml` `[tool.pytest.ini_options] testpaths = ["tests"]`, so a new `tests/test_*.py` is collected automatically.
- `release-please-config.json` treats the whole repo (`"."`) as one `simple` package, so any releasable commit bumps the image version.

Deployed state checked:
- `$MCTL_GITOPS_ROOT/services/admins/` lists `mctl-agents-worker`, `mctl-agents-worker-exec`, `mctl-agents-worker-implement`; `mctl-agents-worker-implement/values.yaml` deploys `ghcr.io/mctlhq/mctl-agents` tag `1.91.0`. This confirms the deployed workers run the image built from this repo's `Dockerfile`; this change must not alter that image's contents. No deployed config is changed by this proposal.
- mctl MCP tools were not called: the change is repo-only (files, tests, CI) and has no runtime or tenant surface to observe.

## Proposed solution

### 1. Crate skeleton `experiments/portable-runtime-rs/`
- `Cargo.toml`:
  ```toml
  [package]
  name = "mctl-runtime"
  version = "0.0.0"
  edition = "2021"
  publish = false
  description = "EXPERIMENTAL spike (#746). Not shipped. Default-off."

  [dependencies]

  # Standalone: never join a parent workspace.
  [workspace]
  ```
  Zero dependencies keeps the lockfile trivially correct without cargo in the implementer image.
- `Cargo.lock`, hand-written by the implementer (cargo is unavailable) and verified by `cargo build --locked` in the spike workflow:
  ```toml
  # This file is automatically @generated by Cargo.
  # It is not intended for manual editing.
  version = 4

  [[package]]
  name = "mctl-runtime"
  version = "0.0.0"
  ```
- `rust-toolchain.toml`: `[toolchain] channel = "1.85.0"`, `components = ["clippy", "rustfmt"]`, `profile = "minimal"`.
- `src/main.rs`: `fn main() { println!("mctl-runtime {}", env!("CARGO_PKG_VERSION")); }` plus a `#[cfg(test)]` module with one trivial test of a `version()` helper so `cargo test` exercises something. No other `.rs` file.
- `README.md`: headline "EXPERIMENTAL — default-off", links #746/#759, states it is not built into the image, not imported by the orchestrator, excluded by `.dockerignore`, guarded by `tests/test_portable_runtime_isolation.py`; run instructions (`cd experiments/portable-runtime-rs && cargo run --locked`); delete instructions (`git rm -r experiments/portable-runtime-rs .github/workflows/portable-runtime-spike.yml`; the isolation test then skips).

### 2. `tests/test_portable_runtime_isolation.py`
Pure functions over text, so the negative self-check reuses the exact detector:
- `REPO_ROOT = Path(__file__).resolve().parents[1]`, `EXPERIMENT = REPO_ROOT / "experiments" / "portable-runtime-rs"`.
- `FORBIDDEN = ("experiments/", "mctl-runtime")`; `GUARDED_DIRS = ("orchestrator", "config", "agents")`; `GUARDED_FILES = ("Dockerfile", "entrypoint.sh", "pyproject.toml", "uv.lock")`.
- `dockerfile_copies_experiments(text) -> list[str]`: returns lines matching `^\s*(COPY|ADD)\b.*\bexperiments\b` (case-insensitive on the instruction).
- `dockerignore_excludes_experiments(text) -> bool`: true if a non-comment, non-negated line, stripped, is one of `experiments`, `experiments/`, `experiments/**`, `/experiments`, `/experiments/`.
- Tests (all except the self-check guarded by `pytest.mark.skipif(not EXPERIMENT.is_dir(), reason=...)`):
  - `test_no_reference_in_shipped_paths`: walk `GUARDED_DIRS` (text files, skipping undecodable bytes and `__pycache__`) and `GUARDED_FILES`; collect `(path, needle)` hits; assert empty with the list in the message.
  - `test_dockerfile_does_not_copy_experiments`.
  - `test_dockerignore_excludes_experiments`.
  - `test_no_cargo_toml_outside_experiment`: `os.walk(REPO_ROOT)` pruning `.git`, `.venv`, `venv`, `_gitops`, `target`, `node_modules`; assert every `Cargo.toml` is under `EXPERIMENT`.
  - `test_detector_flags_injected_copy` (never skipped): `dockerfile_copies_experiments(Dockerfile_text + "\nCOPY experiments/ ./experiments/\n")` is non-empty, and the same detector on the unmodified Dockerfile returns `[]` (when the real file is clean). Also assert `dockerignore_excludes_experiments("experiments/\n")` is true and `("# experiments/\n")` false, so the helper cannot pass vacuously.
- Must pass `ruff check` (line length 120). No new dependencies.

Note: the test file itself contains the forbidden strings, which is fine because `tests/` is not a guarded path.

### 3. Ignore files and commit-lint
- `.gitignore`: append a commented `experiments/**/target/` block.
- `.dockerignore`: append `experiments/` with a comment pointing at the isolation test (defence in depth on top of the explicit `COPY`s).
- `pr-validation.yml` line 134: `SHIPPING_PATHS='^(tests/|docs/|\.github/|experiments/)'`, and update the line 136 message to "under tests/, docs/, .github/ or experiments/". No other job changes.

### 4. `.github/workflows/portable-runtime-spike.yml` (not a required check)
```yaml
name: portable-runtime spike (experimental)
on:
  pull_request:
    paths:
      - "experiments/portable-runtime-rs/**"
      - ".github/workflows/portable-runtime-spike.yml"
  workflow_dispatch:
permissions:
  contents: read
concurrency:
  group: portable-runtime-spike-${{ github.ref }}
  cancel-in-progress: true
jobs:
  cargo:
    strategy:
      fail-fast: false
      matrix:
        os: [ubuntu-latest, macos-14]
    runs-on: ${{ matrix.os }}
    timeout-minutes: 20
    defaults:
      run:
        working-directory: experiments/portable-runtime-rs
    steps:
      - uses: actions/checkout@3d3c42e5aac5ba805825da76410c181273ba90b1 # v7.0.1
        with: { persist-credentials: false }
      - name: Install pinned toolchain
        run: rustup toolchain install   # reads rust-toolchain.toml
      - run: cargo build --locked
      - run: cargo test --locked
      - run: cargo clippy --locked --all-targets -- -D warnings
      - name: Audit dependencies
        run: |
          cargo install cargo-audit --locked --version <pinned>
          cargo audit
```
Uses rustup preinstalled on GitHub-hosted ubuntu and macOS runners, so no third-party Rust action (and no unknown SHA) is introduced; only the already-pinned `actions/checkout` SHA. The workflow file path is included in `paths` so edits to it are validated too.

## Alternatives
- **Generate the lockfile later / omit it**: rejected; the issue requires a committed `Cargo.lock`, and with zero dependencies the v4 lockfile is two stanzas, verified by `--locked` in CI.
- **Use `dtolnay/rust-toolchain` or `rustsec/audit-check` actions**: rejected for slice 1 because their SHAs would have to be pinned without being verifiable from the implementer image; the runners' rustup plus `rust-toolchain.toml` gives the same pin with fewer supply-chain inputs.
- **Enforce isolation via a Dockerfile lint in `pr-validation.yml` only**: rejected; a pytest test runs locally and in the `tests` job, and covers orchestrator/config/agents references that a Dockerfile lint would not.
- **Put the crate under `tools/` or a top-level `rust/`**: rejected; `tools/` is ruff/mypy-checked and shipping, and the issue fixes the `experiments/` location so commit-lint and `.dockerignore` can treat it as one prefix.

## Platform impact
- No migrations, no runtime change, no deployed config change. `orchestrator/`, `config/`, `agents/`, `Dockerfile`, `entrypoint.sh`, `pyproject.toml`, `uv.lock` unchanged; `docker-build` builds identical image contents (`.dockerignore` only shrinks the build context).
- CI cost: spike workflow runs only on PRs touching the experiment or the workflow, two runners, a few minutes (cargo-audit install is the slowest step).
- Risks and mitigations:
  - Hand-written `Cargo.lock` wrong: `cargo build --locked` fails in the spike workflow; fix is a one-line edit. Not a required check, so it cannot block unrelated PRs.
  - `rustup toolchain install` semantics vary across rustup versions on runners: the step fails loudly; fallback is `rustup show` or `rustup toolchain install 1.85.0 --profile minimal -c clippy -c rustfmt`.
  - Commit-lint: this PR touches root `.gitignore`/`.dockerignore`, so it needs a releasable commit subject (`feat(experiments): ...`), producing a version bump with no image-content change.
  - Isolation test false positives (e.g. a future legitimate `mctl-runtime` mention in `config/`): intended; such a reference is exactly what slice 2 must not introduce without an explicit decision.
