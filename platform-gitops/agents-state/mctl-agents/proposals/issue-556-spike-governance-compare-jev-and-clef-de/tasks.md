# Tasks: issue-556-spike-governance-compare-jev-and-clef-de

- [ ] 1. Define the `semantic-decision/v1alpha1` contract in `tools/semantic_decision_spike.py`: the `SemanticDecisionRequest` and `SemanticDecisionResult` dataclasses, the closed vocabularies (categories, recommendations, reason codes, signal statuses), schema validation, and a request builder. The builder takes only canonical `ActionRequest` fields, applies `redaction.contains_credential` and 256-character bounds, and places tool descriptions and model claims under `untrusted`. — DoD: the module is importable with the stdlib plus `httpx`; invalid or credential-shaped input raises; nothing in `orchestrator/` imports it.
- [ ] 2. Implement `combine(det_verdict, result, threshold)` with the strictness order ALLOW < REQUIRE_APPROVAL < DENY (depends on 1). — DoD: it is a pure function that only ever escalates ALLOW to REQUIRE_APPROVAL on `ok` with `HIGH_RISK` at or above the threshold, and returns the deterministic verdict in every other case.
- [ ] 3. Author the fixture set `tests/fixtures/semantic_decision/v1/` (40 or more fixtures, 6 or more per scenario A to D). It covers every class in requirements.md, at least 5 minimal pairs, adversarial and injection descriptions, model-authored authority claims, and sanitized synthetic shapes inspired by mctl-agents#183 and mctl-telegram#602. Each fixture records `deterministic_verdict`, `expected_recommendation`, `danger`, `label_status` and `pair_id`. — DoD: a second reviewer has confirmed the labels; contested labels are marked; no real credentials, private prompts or raw tool output appear.
- [ ] 4. Implement the `DecisionProvider` protocol with `replay`, `typesafe-jev` (resolving the model via `GET /v1/models`) and `cloudflare-clef-flash` providers, plus an optional `cloudflare-clef`. Each has a 1 s timeout, at most 1 retry, response-schema validation and vendor-label mapping, and reports `signal_status` on any deviation (depends on 1). — DoD: the replay provider passes the tests; live providers read credentials only from env and record endpoint, model version and request schema.
- [ ] 5. Implement the `run` command: fixtures x providers x N repeats (default 5), writing one JSONL record per call with all the measurement fields. Raw prompts and completions are written only with `--record-raw DIR` (depends on 2, 3, 4). — DoD: a replay run produces deterministic JSONL; keys denied by the redaction screen never appear.
- [ ] 6. Implement the pure `report` command: JSONL to markdown. It produces the issue's side-by-side table, the deterministic-only baseline, a separate dangerous-false-negative list, the escalation and malformed rates, p50/p95 latency, stability, a 5-bin calibration table with Brier score, the adversarial subset, and cost per 1k/100k/1M decisions at measured token sizes and run-time prices (depends on 5). — DoD: it produces golden output from the recorded JSONL fixture.
- [ ] 7. Operator live run: start a one-off pod in namespace `admins` (same egress as `mctl-agents-worker`), pass vendor credentials through env, run both providers, and keep the JSONL outside the repository except for a sanitized summary (depends on 5, 6). — DoD: measured numbers exist for both providers; the source location, date, resolved model IDs and observed prices are recorded; any unavailable provider or model is reported as such.
- [ ] 8. Write `docs/spikes/556-semantic-decision-models.md`. It contains the results table, per-scenario findings (including an explicit verdict on whether scenario D duplicates CI, Ruff/Pyrefly and the reviewers), answers to the ten questions, the trust boundary and failure semantics, audit and trace fields, self-hosting notes, and one recommendation (`ADOPT_JEV | ADOPT_CLEF_FLASH | LIMITED_GO | NO_GO`) checked against every GO criterion. If the outcome is not NO_GO, it names the proposed integration point in `policy_checkpoint.decide` / the `options.py` PreToolUse hook and the `POLICY_DECISION` fields. If it is NO_GO, it lists replacement deterministic `Rule` candidates and a reuse path for .github#151 and #310 (depends on 7). — DoD: the document is merged; the issue is commented with the recommendation; follow-up issues are filed only for what the recommendation calls for.

## Tests

- [ ] T1. Monotonicity property test: for every fixture, every recommendation, every `signal_status`, and confidence in {0, threshold - epsilon, threshold, 1}, `STRICTNESS[combine(...)] >= STRICTNESS[det]`, and `combine` never returns ALLOW when `det != ALLOW`, and never returns DENY from a model signal.
- [ ] T2. Fail-closed test: the `timeout`, `error`, `malformed` and `low_confidence` results each return the deterministic verdict unchanged.
- [ ] T3. Fixture drift test: each fixture's `deterministic_verdict` equals `policy_checkpoint.evaluate(BUILTIN_POLICY, ActionRequest(...))` (or the named policy variant).
- [ ] T4. Builder screening test: credential-shaped values (matched by `contains_credential`) and over-length values are rejected; untrusted content appears only in the delimited `untrusted` section.
- [ ] T5. Schema validation test: unknown recommendations, categories outside the closed set, missing fields and non-JSON bodies all yield `malformed`.
- [ ] T6. Isolation test: no file under `orchestrator/` references `semantic_decision`, and `policy_checkpoint` exposes no new symbol.
- [ ] T7. Report golden test: `report` over a recorded JSONL fixture yields the expected markdown, including the separate dangerous-false-negative section and the cost rows.
- [ ] T8. No-network test: the replay provider runs the whole `run` + `report` pipeline offline in CI.

## Rollback

The spike only adds files under `tools/`, `tests/` and `docs/spikes/`. Rolling back means reverting the spike PR. No policy, gitops value, secret, migration or production code path is touched, so no runtime state needs restoring. Vendor credentials that were created for the live run should be revoked by the operator after task 7, whatever the outcome.
