## Top 5 Proposals Ready for Review

### 1. Bind the mctl-api 4.155.0 release hold to artifact, chart and runtime flags (with the dark-rollout plan)
- **Service / slugs:** mctl-gitops / `issue-2528-security-release-enforce-mctl-api-4-155` (proposed, updated 2026-11-11) and `issue-2523-deploy-plan-mctl-api-4-155-0-dark-bridge` (proposed, docs-only)
- **What:** Extends the existing `scripts/release-gate.py` and the `mctl-api-bootstrap` hold. An allow record would have to name the exact image digest, source commit, release head and chart revision. The guard would also refuse Bridge and queue runtime keys in the bootstrap values and in the `envFrom` Secrets, and the PR-time check would stop running the PR's own copy of the guard. 2523 supplies the checklist and the one-line `image.tag` bump plan.
- **Why:** Today an allow record is only a set of strings, so a reused or string-only approval could release a different artifact. 4.155.0 bundles the Bridge work (#970/#971) with the deferred execution-request queue, and the owner hold is still in force.
- **Impact 5 / Effort 3.**
- **Conflicts:** None incompatible. 2523 explicitly names an executable guard as a separate mandatory dependency, and 2528 is that guard, so review them together and land 2528 first. The hold also depends on mctl-agents#1007 and mctl-api#935 (see items 5 and "Deferred").

### 2. Temporal JWKS trust path ADR, plus the Glovo P1 isolation decision
- **Service / slugs:** mctl-gitops / `issue-2540-adr-temporal-jwks-trust-path-decision-fo` (proposed) and `issue-2568-security-glovo-canary-choose-and-prove-t` (proposed)
- **What:** 2540 is a decision-only ADR (0004). It picks one authenticated JWKS transport for Vault-signed Temporal workload JWTs, rejects `http://`, and records key rotation, fail-closed behaviour and what the disposable canary must prove. 2568 is a decision record choosing route A (secure the shared frontend) or route B (an isolated Temporal) for Glovo P1, and it keeps P1 BLOCKED until every proof exists.
- **Why:** Per the proposals, the shared Temporal frontend serves plaintext gRPC with no authorizer. Its only boundary is a NetworkPolicy, so any admitted caller can act on every namespace, including the `mctl-agents` DevLoop namespace. The stock claim mapper does not validate `iss`, so the JWKS bytes are the only issuer control.
- **Impact 5 / Effort 2.** Both are decisions, not production changes.
- **Conflicts:** 2568 depends on 2540's outcome. Route B would make much of 2540 unnecessary for Glovo only, so decide 2540 first, then 2568.

### 3. Reconcile the staged Glovo M1 GitOps package, then prepare the immutable canary package
- **Service / slugs:** mctl-gitops / `issue-2567-fix-glovo-canary-reconcile-staged-gitops` (proposed) then `issue-2569-deploy-glovo-canary-prepare-immutable-pr` (proposed)
- **What:** 2567 fixes drift in `deploy/staged/glovo-m1/` (the provider is now an HTTP bridge client, the DB role model changed, and the withdrawn `GLOVO_TEAM_FALLBACK`). It also rewrites the validator, which currently *requires* obsolete values. 2569 adds image supply-chain fields, an MCP ingress shape and a machine-checked evidence and hold registry. Both are render-only and inert.
- **Why:** A later activation PR should copy correct manifests rather than rediscover drift. The validator currently enforces the wrong contract.
- **Impact 4 / Effort 3 (2567), 3 (2569).**
- **Conflicts:** The two edit the same package, validator and CI job, so they collide. Land 2567 first. 2569 also references the DB role wiring from open PR #2563 (A15), which 2567 deliberately does not duplicate.

### 4. Wire the Glovo approval ledger, migrations, receipt sweeper and write fence behind the closed gate
- **Service / slug:** mctl-api / `issue-1004-feat-glovo-wire-the-approval-ledger-migr` (proposed, updated 2026-11-10)
- **What:** Wires all collaborators the write fence needs (receipt fence, work-items pool in the one-database proof, schema application, sweeper, membership-revocation detector). It pins the single writer of `bridge_commands.payload`. The code stays dark behind `glovoWriteFenceHoldLifted = false` and `glovo.ControlDefault.Open = false`.
- **Why:** #985 and #989 are merged but structurally cannot install the fence yet, so the dark launch has an unfinished prerequisite.
- **Impact 4 / Effort 4.** It is a wide wiring change with a migration surface.
- **Conflicts:** Shares the approval surface with governance slice 2 (mctl-api#900, needs-triage) and the W45 approval-binding proposals. It must ship in a version that passes the item 1 guard.

### 5. DevLoop worker rollback boundary (B4): marker-aware rollback check and forward-only emergency path
- **Service / slug:** mctl-agents / `issue-1007-design-devloop-temporal-marker-aware-rol` (proposed, updated 2026-11-09)
- **What:** Adds a marker-aware rollback check, a forward-only emergency runbook and a reproducible Worker Versioning experiment. The owner decision of 2026-11-04 is: forward-only is the baseline, Worker Deployment Versioning is the target, and drain-before-M1 is a fallback.
- **Why:** After M1, any pre-M1 worker that replays a history carrying the `deferred-resume-contract` marker fails with a nondeterminism error. "Roll the image back" is therefore unsafe, including for continue-as-new runs. B4 is a named blocker of the 4.155.0 release gate.
- **Impact 4 / Effort 3.**
- **Conflicts:** None incompatible. The sequence is: land 1007, then lift the release hold in item 1.

## Platform Risks and Cross-Cutting Observations

1. **Shared Temporal has no authorizer.** Per the 2026-11-09 evidence cited in #2540 and #2568, the only boundary is a NetworkPolicy. Several new workloads (Glovo control worker, the DevLoop and the Bridge) all depend on this frontend. Until the ADR and canary land, a compromised admitted pod can act across namespaces. This ties directly to the W45 agent-pod isolation work.
2. **The 4.155.0 hold has many independent prerequisites** (#2528 guard, #1007 rollback boundary, #935 drain, mctl-agents #993 Part M, #992 Part S, and a separate owner GO). A single missed prerequisite should keep the hold on. The guard in item 1 must be merged before anyone removes it.
3. **Dark-launched code is accumulating.** Glovo slices and Bridge code are merged on `main` but deliberately inert (closed gates set as constants). The risk is flag or constant drift and a hasty flip. Item 3 (a machine-checked hold registry) is the right mitigation.
4. **Stuck implementer states persist.** #958 is `review-stuck` and #953 stalled after a `no-commits` one-shot failure, the same pattern flagged in W45 (issue-993, issue-866). Slicing worked, as shown by the merged #959-#961, which supports landing W45's pre-approval implementability check.
5. **Parent and child proposal duplication** (#953/#954 against their slices, #1051 against #1052) clutters the queue and risks someone approving a superseded proposal.
6. **Unverified live state.** Confirm the actual production mctl-api version (expected `4.154.0`), any open incidents on Temporal or the Bridge, and tenant limits before acting on any item above. This could not be done this week.
7. **Carry-over from W45:** the incident-proposal backlog (about 236 `incident-*` items) and the merge-conflict parking of issue-2289 and issue-2292 were not re-reviewed this week and still need an operator pass.
