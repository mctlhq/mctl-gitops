## Top 5 Proposals Ready for Review

### 1. Credential-separated, policy-mediated Bash for the model shell
- **Service / slug:** mctl-agents / `issue-869-feat-agents-credential-separated-policy` (updated 2026-11-18)
- **What:** Run every model `Bash` command through an allowlisted-environment wrapper (set via `CLAUDE_CODE_SHELL_PREFIX`). The session fails closed if the wrapper is missing or altered. Credentialed operations (push, PR creation, GitHub reads) move to the orchestrator process or to a policy-checked in-process MCP server, `github_read`.
- **Why:** Today Bash is audit-only. The proposal reports that in the investigator's own session (2026-11-18) model Bash had a non-empty `GITHUB_TOKEN` and a readable `GITHUB_TOKEN_FILE`. Repository build and test scripts run by the model inherit them. The scrub list is a denylist and misses these two.
- **Impact 5 / Effort 3.** The tests include a mutation check that fails if the full environment is restored.
- **Conflicts:** None incompatible. The proposal itself leaves a residual: a same-uid shell can still read `/proc/<pid>/environ` and mounted credential files. That belongs to the pod-level work (#807 G2), so this should not be treated as complete isolation. It is complementary to the audit-only Bash classifier (#865) and to the W45 agent-pod isolation work. One open question matters: the exact contract of the shell prefix in the pinned CLI (claude-agent-sdk 0.2.174) is unverified, so the first task must verify it against the real binary.

### 2. Argo Rollouts assessment, including the auto-promote default
- **Service / slug:** mctl-gitops / `issue-2668-spike-assess-argo-rollouts-for-evidence` (updated 2026-11-15)
- **What:** A research-only decision memo with one verdict (`KEEP_NATIVE_DEPLOYMENTS`, `BOUNDED_ROLLOUTS_PILOT`, `ADOPT_GATED_PROGRESSIVE_DELIVERY` or `DEFER_UNTIL_RELEASE_GATES_READY`). It includes an offline fixture proving that inconclusive or unavailable metrics end in pause or abort, never in promotion.
- **Why:** The proposal found that the Argo Rollouts controller is already declared in `platform-gitops/bootstrap`, and that the base-service chart renders a blue-green `Rollout` with `autoPromotionEnabled: true` and no analysis. No service opts in today, so it is dormant but ungated. That finding is worth a follow-up whatever the verdict is.
- **Impact 3 / Effort 2.** No cluster change is authorized.
- **Conflicts:** The proposed primary candidate, mctl-api, sits under the active release hold (`mctl-api-bootstrap`), so the low-risk control (`admins/mctl-docs`) is the safer pilot candidate. Must not weaken `release-gates.yaml`. Overlaps in theme with #2828 and the W46 hold work, so review it alongside #2828.

### 3. Governed release calendar (S0 research, revision 3)
- **Service / slug:** mctl-gitops / `issue-2828-spike-release-governed-release-calendar` (updated 2026-11-20)
- **What:** Research on the smallest safe way to enforce deployment freezes. The hybrid design is a canonical window policy judged at GitOps write points, Argo CD sync windows as a secondary safeguard, and a candidate "Governed Sync Broker" that spends one MFA grant from the existing mctl-api ledger for an exception. S0 only (inventory, offline model, inert local harness, decision memo). Accepting the proposal is explicitly not the owner GO to run S0.
- **Why:** Freezes are currently convention, and the 4.155.0 hold shows how much manual coordination the release path needs. The proposal is honest about scope: "image-bump window policy (partial coverage)", with the effective outcome `REUSE_EXISTING_ONLY` until the owner decides.
- **Impact 4 / Effort 4.** It is already on revision 3 after an independent review (4 P1, 5 P2, 3 P3) and is large.
- **Conflicts:** Reuses `release-gate.py`, the release ledger and the mctl-api approval path, so it must be sequenced after the W46 guard (#2528) and must not create a second approval authority. The broker option touches the Argo CD RBAC surface, which needs a separate security GO (S3).

### 4. Narrow baseline-comparison fix for the context eval
- **Service / slug:** mctl-agents / `issue-1014-spike-do-devloop-success-metrics-detect` (updated 2026-11-18, narrowed by the owner on 2026-11-17)
- **What:** Make `test_baseline_matches` symmetric and identity-aware. It would flag cases or strategies that disappear from or are missing in the baseline, extra or deleted metrics, an explicit `None` versus an absent key, and an unchecked baseline `_header`. Exact comparison, no tolerance introduced.
- **Why:** The current drift check iterates expected-only, so real regressions in the context eval can pass silently. The fix is small and test-only.
- **Impact 2 / Effort 1.** The cheapest item this week.
- **Conflicts:** None. It supersedes the earlier broad plan. The related research PR #1082 is still open and unmerged. Re-check for parallel branches touching `context_eval` before implementing.

### 5. MCP tool-exposure benchmark, with the Code Mode experiment as a companion
- **Service / slugs:** mctl-agents / `issue-597-spike-enterprise-mcp-benchmark-context-e` and `issue-1096-spike-devloop-evaluate-claude-code-code` (both updated 2026-11-18)
- **What:** 597 builds the offline parts of a decision benchmark (task oracles, run-record tooling in `tools/capability_bench.py`, a pre-registered decision rule) comparing four tool-exposure modes. Its final recommendation is one of `ADOPT_MCTL_NATIVE`, `ADOPT_PORTAL_MODE`, `HYBRID` or `DEFER`. 1096 is a research-only spike on whether interactive Claude Code "Code Mode" helps operator research without losing per-action governance.
- **Why:** The only measurement so far is a single run per mode (-62% first-turn tokens, but no end-to-end saving: 30 against 52 turns, $5.24 against $6.10). Cost effectiveness is unproven, and the choice affects every agent run.
- **Impact 3 / Effort 3 (597), 2 (1096).**
- **Conflicts:** 1096 is explicitly a non-comparable adjunct slot to 597, so review them together. Measured runs are operator steps gated on plan approval. All unmeasured cells stay `NOT_RUN`. Neither may reopen the parked Cloudflare portal (mctlhq/.github#63, parked on an audit-correlation failure).

## Platform Risks and Cross-Cutting Observations

1. **Recurring root-app and mctl-agents-worker sync alerts.** The same two applications keep re-alerting, and the root-app proposals say no skill matched and that log lookup fails with "tenant not found: argocd". This is a blind spot: the incident responder cannot analyse app-of-apps failures. A single triage skill for ArgoCD application-level alerts would likely close about 11 of the 18 refreshed incident proposals.
2. **mctl-api instability signals during a release hold.** Incident proposals from 2026-11-16 to 2026-11-20 report a crash loop, a stuck rollout and a degraded `admins-mctl-api` application. They sit alongside the 4.155.0 hold from W46. I could not verify live state, so confirm the running version and whether these incidents are open before reviewing any mctl-api release item. If they are connected to the hold or the Bridge dark launch, that raises the priority of W46 item 1 (#2528).
3. **Credentials in model shells.** #869 reports a live observation of credentials reachable from model Bash. Until it lands, any repository code the agents run can read the GitHub token. Combined with the W46 observation that the shared Temporal frontend has no authorizer, agent-pod isolation is the main cross-cutting security gap.
4. **Dormant but ungated capability.** Argo Rollouts is installed with an auto-promote default and no analysis (#2668). Nobody should enable `blueGreen` before an analysis gate exists.
5. **Quota pressure.** `KubeQuotaFullyUsed` fired for `labs-preview` and `admins`, and `KubeJobFailed` for `mctl-glovo`. I could not check tenant resource limits. Verify them before the Glovo canary work (W46 items 3 and 4) adds more workloads.
6. **Large research-only proposals.** #2828 is on revision 3 and several spikes carry long review histories. Each explicitly authorizes nothing, so the review risk is scope creep, not production risk. Ask owners for a GO or NO-GO per stage.
7. **Unverified live state.** No mctl tools were available, so versions, open incidents and tenant limits were not cross-checked this week.
8. **Carry-over:** the incident-proposal backlog (about 236 items at W46) and the open W45 and W46 items remain unreviewed by an operator.
