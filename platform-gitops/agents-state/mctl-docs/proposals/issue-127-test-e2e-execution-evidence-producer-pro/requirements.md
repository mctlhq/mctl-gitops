# Document execution-evidence envelopes in the shepherd section of the MCP tools reference

## Context
Issue mctlhq/mctl-docs#127 asks for one sentence in `docs/mcp/tools-reference.md`, under the
`### mctl_trigger_shepherd` section, stating that each governed agent run records a sealed
execution-evidence envelope in mctl-api. The issue is an end-to-end test fixture for
mctlhq/mctl-agents#199 (execution evidence): its real purpose is to produce an investigate-run
evidence record, and the issue explicitly states the proposal is not to be implemented and
will be rejected after the proof.

The proposal is still written as a complete, implementable spec so that the investigate run
exercises the normal path. If it were implemented, operators reading the shepherd docs would
learn that governed runs leave a durable, tamper-evident record in mctl-api.

## User stories
- AS a platform operator I WANT the shepherd docs to mention that governed agent runs record a
  sealed execution-evidence envelope in mctl-api SO THAT I know an auditable record of each run exists.
- AS the mctl-agents owner I WANT this investigate run to complete with a full proposal SO THAT
  the execution-evidence producer proof (mctl-agents#199) has a durable evidence write to query and replay.

## Acceptance criteria (EARS)
- WHEN the change is applied THE SYSTEM SHALL contain exactly one new sentence in
  `docs/mcp/tools-reference.md`, inside the `### mctl_trigger_shepherd` section (between that
  heading and the next `---` separator), stating that each governed agent run records a sealed
  execution-evidence envelope in mctl-api.
- WHEN the change is applied THE SYSTEM SHALL leave every other line of
  `docs/mcp/tools-reference.md` unchanged.
- WHEN `bun run build` runs THE SYSTEM SHALL regenerate `docs/public/llms-full.txt` so that it
  contains the new sentence, and the VitePress build SHALL succeed.
- WHILE the sentence is present THE SYSTEM SHALL keep repo conventions: English, no emoji.
- IF the proposal is rejected as the issue states THEN THE SYSTEM SHALL have no change merged to
  `mctl-docs`.

## Out of scope
- Implementing or merging this change (the issue says it will be rejected after the proof).
- Documenting the execution-evidence API, schema, query tools, or replay dedupe semantics.
- Adding evidence documentation to any other tool section (e.g. `mctl_trigger_implementer`,
  `mctl_trigger_issue`) or other pages.
- Changes to mctl-api or mctl-agents.

## Open questions
- "Governed agent run" is not defined anywhere in `docs/`; the sentence uses the term as given.
  If implemented for real, a link to a page defining governed runs and evidence would be needed.
- The issue does not state where in the section the sentence goes; this proposal places it as a
  new paragraph after the cron paragraph and before `**Parameters:**`.
- Whether the regenerated `docs/public/llms-full.txt` should be committed with the change (it is
  tracked in git and also regenerated by `bun run build`). This proposal regenerates and commits it
  to keep the tracked copy consistent.
