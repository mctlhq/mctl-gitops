# Design: issue-125-test-e2e-add-an-approval-gate-note-to-th

## Current state
- There is no `README.md` at the repository root. The top level holds `CHANGELOG.md`, `SECURITY.md`, `LICENSE`, `package.json`, `release-please-config.json`, `.release-please-manifest.json` and the `docs/` VitePress tree.
- `CHANGELOG.md` is produced by release-please: `.github/workflows/release-please.yml`, with `release-please-config.json` mapping the `feat`/`fix`/`docs`/`deps` commit types to changelog sections. Editing it by hand would collide with release-please and break the "do not touch release configuration" constraint.
- `docs/mcp/tools-reference.md` already describes the agent merge path. The `### mctl_trigger_shepherd` section says the shepherd scans implementer PRs (`feat/agents-*` branches) and, in step 3, "If the review is clean and CI is green, merges the PR with `--merge --delete-branch` and flips the proposal's `.status.yaml` to `status: merged`." Right after the numbered list is a paragraph about the `30 */2 * * *` cron.
- `package.json` `build` runs `bun run generate:llms && vitepress build docs`. `scripts/generate-llms-full.ts` rebuilds `docs/public/llms-full.txt` from the Markdown sources on every build, including the Docker build.

## Proposed solution
Add one sentence to `docs/mcp/tools-reference.md`, in the `### mctl_trigger_shepherd` section, as its own paragraph directly after the numbered list (steps 1-4) and before the "The shepherd also runs autonomously..." paragraph. Suggested wording:

> In this repository (mctl-docs), the platform may require an explicit human approval (an action-approval receipt) before it merges an agent-authored PR.

Why here: this is the one existing page that documents the shepherd's merge, so a reader learns about the gate at the point where the merge is described. Putting it in its own paragraph leaves step 3's existing text unchanged and keeps the diff to a single hunk.

Commit as `docs: note that agent-authored PR merges may require human approval` so release-please records it under "Documentation" without anyone editing `CHANGELOG.md`.

Do not commit a regenerated `docs/public/llms-full.txt`. It is rebuilt at build time, and keeping it out keeps the diff to one sentence, as the issue requires.

## Alternatives
- Edit `CHANGELOG.md` (the title's "docs changelog"): dropped. The file is generated by release-please and the issue forbids touching release configuration. The `docs:` commit gets a changelog line anyway.
- Create a `README.md` with the sentence: dropped. The issue says "no new pages", and a one-line README would be an odd new top-level artifact.
- Add it to `docs/human-input/semantics.md` or `SECURITY.md`: dropped. Human-input covers clarification questions, not merge approval, and `SECURITY.md` covers vulnerability reporting and CSP. Neither describes the shepherd's merge.

## Platform impact
- No migrations, no config, no dependency changes, no runtime behavior change.
- Backward compatibility: not applicable (static content).
- Resource impact: none. The rebuilt site grows by one sentence.
- Risk: the sentence could overstate the gate. Mitigation: use "may require" and the issue's own scope ("in this repository").
- Risk: the tracked `docs/public/llms-full.txt` falls one sentence behind the source until the next build regenerates it. This is accepted and matches how that file is produced now.
- Process note: the merge of this PR is the action under test (mctl-agents#198). Reviewers should expect it to wait in WAITING_FOR_APPROVAL and should not hand-merge it outside the approval flow.
