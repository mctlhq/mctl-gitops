# Design: issue-124-docs-connect-your-first-client-page-huma

## Current state
- Site: VitePress, content under `docs/`, config in `docs/.vitepress/config.ts`
  (`cleanUrls: true`, local search, sidebar groups "Getting Started", "Platform",
  "Guides", "MCP Server", "Human Input", "Security", "API", "Reference").
- The "Guides" sidebar group lists, in order, `First-user checklist`
  (`/guides/first-user-checklist`) then `Deploy your first app`
  (`/guides/deploy-first-app`), then tenants, services, etc.
- Connection content is spread across three MCP-first pages:
  - `docs/getting-started/index.md` "Step 2: Connect your AI client" (Claude.ai,
    Claude Code `claude mcp add mctl --transport http https://api.mctl.ai/mcp`,
    Cursor / VS Code) and "Step 3: Verify your connection".
  - `docs/mcp/connecting.md` with the `<McpSetup />` component
    (`docs/.vitepress/theme/components/McpSetup.vue`) for the GitHub OAuth flow,
    verification via "Who am I on MCTL?" / `mctl_whoami`, and token types.
  - `docs/guides/first-user-checklist.md`, an access checklist (portal, ArgoCD,
    Argo Workflows, repo).
- Telegram: the `/mctl link` and `/mctl work` commands appear nowhere in `docs/`.
  `docs/human-input/surface-identity.md` documents the surface identity link
  (one-time code, `telegram:<id> <-> github:<login>`) as merged but not deployed, and
  `docs/human-input/architecture.md` lists the Telegram surface as blocked.
- `docs/public/llms.txt` is a hand-maintained index (e.g. line 8 links the MCP
  Connecting guide); `docs/public/llms-full.txt` is generated by
  `scripts/generate-llms-full.ts`, which concatenates every `.md` under `docs/` and
  runs as part of `bun run build`.
- No page in `docs/` embeds screenshots.

## Proposed solution
Add one new page, `docs/guides/connect-first-client.md`, and register it.

Page structure (lead = MCP connector, per the assumption in requirements.md):
1. Intro: who the page is for (just given access), what "connected" means (you can run
   `mctl_whoami`), and a one-line note that two paths are equally supported.
2. "Before you start": GitHub account with MCTL access; a desktop AI client that
   supports remote MCP (Claude, Claude Code, Cursor, VS Code).
3. "Connect with the MCP connector" (numbered lead procedure): add the remote
   connector `https://api.mctl.ai/mcp`, complete OAuth via [Connecting](/mcp/connecting)
   (link, do not duplicate `<McpSetup />`), then verify with "Who am I on MCTL?".
4. "Alternative: connect from Telegram": `/mctl link` to link your Telegram account to
   your GitHub identity, then `/mctl work`. Kept to the command names and order from
   the issue; link to `/human-input/surface-identity` for how linking works. No
   unconfirmed behaviour details.
5. "Next steps": links to `/guides/first-user-checklist` and `/guides/deploy-first-app`.

The two path sections are self-contained so that, if the decision is Telegram-first,
the implementer swaps sections 3 and 4, swaps the "Before you start" prerequisites, and
retitles them; nothing else in the page or config changes.

Registration:
- `docs/.vitepress/config.ts`: in the "Guides" sidebar group insert
  `{ text: 'Connect your first client', link: '/guides/connect-first-client' }`
  between the "First-user checklist" and "Deploy your first app" entries.
- `docs/public/llms.txt`: add one line in the same style as the existing entries.
- `docs/getting-started/index.md` Step 2: optional one-line tip linking to the new page.
- `docs/public/llms-full.txt` is regenerated by the build.

Tone, length and format follow existing guides (e.g. `first-user-checklist.md`): plain
Markdown, VitePress `::: tip` containers where useful, no emoji, English.

## Alternatives
- Put the page in the "Getting Started" sidebar group next to "Quick Start". Dropped:
  that group holds a single end-to-end quick start, while onboarding steps such as the
  first-user checklist live in "Guides"; the new page belongs with them.
- Extend `docs/mcp/connecting.md` with a Telegram section. Dropped: that page is MCP
  reference scoped under "MCP Server"; the issue asks for a single page that presents
  both paths with one lead, aimed at new users.
- Present both paths side by side as VitePress code-group/tabs with equal weight.
  Dropped: the issue explicitly requires leading with exactly one path.

## Platform impact
- Migrations: none. Static docs only.
- Backward compatibility: additive; no existing URL changes.
- Resources: one extra static page; negligible build size change.
- Risks and mitigations:
  - Wrong lead path: the lead is an unrecorded product decision. Mitigation: a
    clarification question is filed; sections are self-contained so a swap is local.
  - Inaccurate Telegram details: commands are undocumented in this repo and the
    Telegram surface is described as blocked in `docs/human-input/architecture.md`.
    Mitigation: document only command names and order from the issue; confirm with the
    mctl-telegram owners before publishing.
  - Dead links: verified by `bun run build`.
- This issue is a controlled E2E test; the proposal must not be approved or implemented.
