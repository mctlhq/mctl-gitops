### Commits f5e1437, 7439573, ca41c90, 82d75fd, 2ef473e, 217e225, f9fa393 — OAuth Dynamic Client Registration hardening
- **Date:** 2026-08-16 (all shipped in release 4.32.5)
- **Type:** fix (one connected hardening story, 7 commits)
- **User-visible effect (verified via diff on 217e225 and f9fa393, subjects for the rest):**
  - `/oauth/register` rate limit raised from 5/min to **30/min per IP** — the previous limit 429'd legitimate multi-process desktop MCP clients (e.g. Antigravity CLI, which fans out ~8 registration calls on cold start) out of ever getting a token.
  - The DCR client registry is now bounded and evicts old entries (`OAuthServer.MaxRegisteredClients`) instead of growing unbounded — stale registrations expire.
  - `OAUTH_TOKEN_TTL` is now capped server-side at **24h max**; the server refuses to start if configured higher (`cfg.validate()` in `cmd/api/main.go`). Rationale recorded in the commit: access tokens have no revocation path, so an unbounded TTL is an unbounded leak window (a sibling service, mctl-telegram, apparently hit this with a leaked year-long token).
  - Revocation requests without a token are now rejected instead of silently accepted; a revocation of a token that was never valid no longer returns a false `200 OK`.
  - `client_name` is now length-bounded in registration success logs.
  - Rejected `redirect_uri`s are now named in the registration failure response (easier to self-diagnose a bad client config).
- **Docs:** **gap**. Verified: `docs/mcp/connecting.md` describes the three token types but nothing about DCR limits, token TTL, or revocation semantics. `docs/reference/troubleshooting.md`'s "MCP Connection" / "Token type confusion" sections don't mention token expiry or registration limits either — a user whose OAuth client hits the new 24h TTL or gets rate-limited during a multi-process cold start has no page telling them what to expect.
- **Suggested doc location:** `docs/mcp/connecting.md` (new "Token Lifetime & Client Registration" subsection) + a new troubleshooting entry under `docs/reference/troubleshooting.md`.
