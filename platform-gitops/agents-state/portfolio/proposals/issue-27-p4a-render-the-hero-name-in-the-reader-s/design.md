# Design: issue-27-p4a-render-the-hero-name-in-the-reader-s

## Current state

**The bilingual mechanism.** `src/i18n/Lang.astro` is a two-prop component
whose whole body is:

```
<span class="l en">{en}</span><span class="l ru" lang="ru">{ru}</span>
```

`src/styles/site.css` hides one half per document language with
`:root[data-lang='en'] .l.ru { display: none }` and its mirror. The
`data-lang` attribute is authored as `en` in `src/layouts/Base.astro` and
overwritten by the ~400-byte inline script in `<head>` from `localStorage`, so
English is what renders with JavaScript disabled. Strings come from the `ui`
object in `src/i18n/ui.ts`, where every entry is an `{ en, ru }` pair;
`test/ui.test.ts` already walks the whole object and asserts both halves exist,
are the same kind (string vs array), and are non-empty.

**The hero.** `src/pages/index.astro` line 19 is:

```
<h1 class="hero-name">Dmitrii Mashkov</h1>
```

It is the only user-facing string on the page not passed through `Lang`. The
thesis, subline, stat labels, stat caption, CTAs and all three `Details` blocks
below it all are. `ui.homeTitle` (`{ en: 'Dmitrii Mashkov', ru: 'Dmitrii
Mashkov' }`) is a separate entry used only as the `title` prop of
`Base.astro`, which emits it into `<title>{title}</title>` as a single string —
`<title>` cannot hold a toggled pair.

**The typography.** `src/styles/site.css` sets

```
.hero-name {
  font-family: var(--font-editorial);
  font-size: var(--mctl-typography-font-size-hero);
  line-height: var(--mctl-typography-line-height-hero);
  letter-spacing: var(--mctl-typography-letter-spacing-hero);
  margin-block: var(--mctl-space-6) var(--mctl-space-4);
}
```

The custom-property chain lives in the vendored `public/assets/mctl/mctl.css`:
`--font-editorial: var(--mctl-typography-font-family-editorial)` (line 378) and
`--mctl-typography-font-family-editorial: 'Instrument Serif', Georgia, serif`
(line 168). The display chain next to it is
`--font-display: var(--mctl-typography-font-family-display)` →
`'Onest', system-ui, -apple-system, sans-serif`. Every other rule in
`site.css` that names a family uses `--font-display` or `--font-mono`;
`.hero-name` is the single `--font-editorial` user in this repository's own CSS
(the vendored `prose.css` uses it too, for blockquotes and headings, which is
why the family is not orphaned by this change).

`public/assets/fonts/fonts.css` is generated by `scripts/vendor-assets.mjs`.
Instrument Serif appears there in two subsets only — `latin` and `latin-ext`,
weight 400, normal and italic — with `unicode-range: U+0000-00FF,...` and no
Cyrillic block. Onest appears at weights 300–700 across `latin`, `latin-ext`,
`cyrillic` (`unicode-range: U+0301,U+0400-045F,U+0490-0491,U+04B0-04B1,U+2116`)
and `cyrillic-ext`. So `Дмитрий Машков` set in Instrument Serif would render
entirely from `Georgia, serif`; set in Onest it renders from
`onest-cyrillic-*-normal.woff2`, the same family as the rest of the page.

**The checking machinery.** `npm test` runs
`scripts/check-no-metrics.mjs` (scans `src/pages`, `src/components`,
`src/layouts` for typed numbers), `scripts/check-contrast.mjs`, then fourteen
`node --test` files. It cannot see `dist/`, because `prebuild` is
`npm run vendor && npm test` and therefore runs *before* `astro build` — the
header comment of `scripts/check-dist.mjs` says exactly this. `check-dist.mjs`
is the post-build gate: it walks `dist/`, fails on any `.js` file, fails on any
HTML file whose `class="l en"` count differs from its `class="l ru"` count,
enforces a 40 KB cap on `dist/index.html`, and carries per-page sections
(`checkApproachPage`, `checkColophonPages`, `checkSitemap`) added by earlier
cycles. It runs in the `Dockerfile` builder stage
(`RUN npm run build && node scripts/check-dist.mjs && node scripts/csp-hash.mjs ...`),
so the `build` job of `.github/workflows/build.yml` exercises it on every pull
request by building the image.

`test/home.test.ts` is the source-level companion for the home page; it reads
`src/pages/index.astro` as text and asserts, among other things, that the
rendered template contains no digit and that both CTAs keep trailing-slash
hrefs. `test/a11y.test.ts` reads `src/styles/site.css` with comments stripped
and parses rule blocks by selector — the precedent for asserting on a CSS rule
from a Node test.

## Proposed solution

Four files change; no new file is created.

**1. `src/i18n/ui.ts` — add the pair.** Insert next to `homeTitle`:

```ts
heroName: { en: 'Dmitrii Mashkov', ru: 'Дмитрий Машков' },
```

and replace the stale comment above `homeTitle` (it currently claims "The name
is identical in both languages", which is false — the two forms are different
scripts, which is precisely why Instrument Serif cannot set the Russian half)
with one that states the split: `heroName` is the prose pair, `homeTitle` is
the single-string `<title>` value and stays Latin on both sides. `homeTitle`'s
value is not touched. Because `ui` is `as const` and `test/ui.test.ts`
iterates the whole object, the new entry is type-checked by `npm run check`
and shape-checked by the existing suite for free.

**2. `src/pages/index.astro` — render through `Lang`.** Replace line 19 with:

```astro
<h1 class="hero-name"><Lang en={ui.heroName.en} ru={ui.heroName.ru} /></h1>
```

`Lang` is already imported in the frontmatter, as is `ui`. The emitted markup
becomes
`<h1 class="hero-name"><span class="l en">Dmitrii Mashkov</span><span class="l ru" lang="ru">Дмитрий Машков</span></h1>`,
which satisfies the `class="l en"` / `class="l ru"` criteria, adds one to each
parity count (so the counts stay equal), and gives the Russian half a
`lang="ru"` attribute for screen readers at no extra cost — the same property
`docs/accessibility-checklist.md` already claims for every other Russian block.
The two spans are inline-level inside a block `<h1>`, and exactly one of them
is `display: none` at any time, so the hero keeps rendering as a single line of
text with no layout change. The `description` prop above it is untouched: it is
a `<meta>` value, one string, outside this issue's scope.

**3. `src/styles/site.css` — move the hero to Onest.** In the `.hero-name`
rule, `font-family: var(--font-editorial)` becomes
`font-family: var(--font-display)`, and an explicit
`font-weight: var(--mctl-typography-font-weight-bold);` is added. Using the
existing `--font-display` token rather than a literal `'Onest', ...` stack
keeps the design-system indirection every other rule in the file uses, and
resolves to a stack whose first family is `Onest`. The explicit weight is
there because `.hero-name` declares none today and inherits the user agent's
bold default for `<h1>`: Instrument Serif ships weight 400 only, so the current
hero is a synthesized bold, while Onest ships a real 700 face. Declaring 700
makes the resulting weight a decision in the file rather than an accident of
which faces happen to exist. `font-size`, `line-height`, `letter-spacing` and
`margin-block` are unchanged; the `-0.02em` hero tracking is a sane setting for
Onest at `clamp(48px, 8.4vw, 132px)`. No other rule in the file is touched, so
`test/a11y.test.ts`'s min-target and no-animation assertions are unaffected.
`npm run vendor` copies this file to `public/styles/site.css` (gitignored,
regenerated on every `prebuild`), so no vendored artifact is hand-edited.

**4. Tests — three layers, each at the layer that can actually see the thing.**

*Dictionary (`test/ui.test.ts`).* One new test asserting the exact copy
character for character (`heroName.en === 'Dmitrii Mashkov'`,
`heroName.ru === 'Дмитрий Машков'`), that the two differ, and that
`homeTitle.en === homeTitle.ru === 'Dmitrii Mashkov'`. The difference assertion
is what makes a future collapse back to one string fail the suite; the
`homeTitle` assertion is what stops someone "finishing the job" by
Cyrillicising the `<title>`.

*Page and CSS (`test/home.test.ts`).* Three new tests, all source-level:
(a) the template of `src/pages/index.astro` contains
`<h1 class="hero-name">` wrapping a `<Lang` element bound to `ui.heroName.en`
and `ui.heroName.ru`, and the template contains neither `Dmitrii Mashkov` nor
`Дмитрий Машков` as a literal (the existing `description` prop lives in the
frontmatter, above the split point `test/home.test.ts` already computes, so it
does not trip this);
(b) the `.hero-name` rule in `src/styles/site.css`, comments stripped, declares
a `font-family` whose `var(--...)` chain — resolved by reading the
`--font-*` and `--mctl-typography-font-family-*` declarations out of
`public/assets/mctl/mctl.css`, not by hard-coding the answer — yields a stack
whose first family is `Onest`;
(c) that same resolved stack, and the rule's own text, contain no
`Instrument Serif`.
Resolving the chain rather than string-matching `var(--font-display)` is what
makes (b) a real check of criterion 3: if the design system ever repoints
`--font-display`, the test fails instead of passing on a token name.

*Built output (`scripts/check-dist.mjs`).* A new `checkHomePage()` section,
in the shape of the existing `checkApproachPage()`, reading
`dist/index.html` and reporting a problem when: the `<h1 ... class="hero-name">`
element is absent; it does not contain `Dmitrii Mashkov` inside an element
carrying `class="l en"`; it does not contain `Дмитрий Машков` inside an element
carrying `class="l ru"`; or `<title>` is not exactly `Dmitrii Mashkov` / holds
any character in `U+0400-U+04FF`. Its problems are appended in `main()` next to
the other sections' problems. The page-wide parity and no-`.js` criteria need
no new code — `main()` already enforces both for every HTML file under `dist/`,
and the hero's new pair is counted by it automatically.

Why split this way: criteria 1, 2 and 4 are statements about emitted HTML and
only `check-dist.mjs` can see emitted HTML; criterion 3 is a statement about
CSS that no browserless runner can *compute*, so the honest mechanical proxy is
a resolved-var-chain assertion in `npm test`; criterion 6 is a statement about
the dictionary and belongs where the dictionary is tested. Nothing is asserted
in a place that cannot observe it, and nothing is asserted twice in a way that
lets one copy drift.

## Alternatives

**Hard-code the family as `font-family: 'Onest', system-ui, sans-serif` in
`.hero-name`.** This trivially satisfies "resolves to Onest first, and
`Instrument Serif` appears nowhere in that rule" and needs no var-chain
resolution in the test. Dropped: every other family declaration in
`src/styles/site.css` goes through a design-system token, and a literal stack
here would silently diverge from `@mctlhq/css` the next time the display family
is repointed. The token indirection is the convention, and the test can resolve
it.

**Keep the hero in Instrument Serif and set only the Russian half in Onest**
(e.g. `.hero-name .l.ru { font-family: var(--font-display) }`). Dropped: it
makes the same name render in two unrelated faces depending on the toggle,
which is a worse typographic result than either family alone, and it
contradicts `AGENTS.md`, which says the hero "is set in Onest" — singular, for
the element, not per language half.

**Transliterate on the fly, or hold the name in `homeTitle` and reuse it for
the `<h1>`.** Dropped: transliteration is exactly the failure the issue
describes (a page that reads as translated), and reusing `homeTitle` would
force the `<title>` and the hero to move together — the next person who wants
a Cyrillic hero would get a Cyrillic browser tab, which `AGENTS.md` explicitly
rules out. Two entries with two jobs and a test pinning each is the cheaper
invariant.

**Put the built-output assertions in `npm test` instead of
`check-dist.mjs`.** Dropped as impossible rather than undesirable: `prebuild`
runs `npm test` before `astro build`, so `dist/` does not exist when the suite
runs. Making the suite build the site first would turn a sub-second unit run
into a full build on every invocation and would recurse through `prebuild`.

## Platform impact

- **Migrations:** none. No data, no schema, no stored state. The site is
  static output served by nginx.
- **Backward compatibility:** no URL, route, header or asset path changes.
  `dist/index.html` gains roughly 60 bytes (one extra `<span>` pair plus the
  Russian name in UTF-8) against a 40 KB cap that current output is far under —
  `check-dist.mjs` reports the exact figure on every image build, so a
  regression here is loud.
- **Resource impact:** the Onest Cyrillic subset (`onest-cyrillic-*-normal.woff2`)
  is already vendored, already linked from `public/assets/fonts/fonts.css`, and
  already fetched by any reader who toggles Russian, because every other
  Russian string on the page is set in Onest. Moving the hero to it adds no
  request. Instrument Serif's two Latin faces stay vendored and stay in use via
  the vendored `prose.css`, so no licence file or font file is removed and
  `scripts/vendor-assets.mjs` needs no change.
- **CSP and ADR-0002:** no new script, no `<style>` element, no inline
  `style=` attribute, no `.js` under `dist/`. `scripts/csp-hash.mjs` still sees
  exactly one inline script and its hash is unchanged, because
  `src/layouts/Base.astro` is untouched.
- **Risk — the hero looks different.** True and intended: a serif hero becomes
  a sans hero. Mitigation: it is the documented `AGENTS.md` position, the size
  and tracking tokens are unchanged, and the weight is now declared rather than
  synthesized. Visual confirmation is a reviewer step (open the page, toggle
  RU), never an acceptance criterion — an agent cannot run a browser.
- **Risk — a future `npm run vendor` repoints `--font-display`.** The
  resolved-chain test in `test/home.test.ts` fails in that case rather than
  passing on a token name, and `scripts/vendor-assets.mjs` already pins
  `mctl.css` by SHA-256, so any such change is a deliberate re-pin.
- **Risk — the parity counter drifts.** Adding a pair adds exactly one to each
  side. `check-dist.mjs` compares the two counts for every HTML file under
  `dist/` and fails the image build on a mismatch, so a half-finished edit
  cannot ship.
- **Rollback:** a single revert commit; see `tasks.md`.
