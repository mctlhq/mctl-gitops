# Design: issue-71-q9-the-six-p3-findings-from-69-four-are

## Current state

### `scripts/check-dist.mjs` (925 lines, no entry-point guard)

`main()` is declared at line 830 and called unconditionally at line 925 --
`await main();`, no `isEntryPoint()` wrapper, no `try/catch`. The function
accumulates every problem into a local `problems` array, prints them all with
`console.error` and sets `process.exitCode = 1` (lines 913-919). The ordering
matters for this cycle: the HTML loop (lines 855-881) calls
`checkNavigationState()`, `checkOgImageMeta()` and `checkHashedSubresources()`
per file, then `checkHomePage()`, `checkApproachPage()`, `checkColophonPages()`,
`checkSitemap()` and `checkOgPngDimensions()` run afterwards (lines 890-908).
Anything that throws anywhere in that chain aborts before the report prints.

`checkSitemap()` (line 758) already guards `siteOrigin()`:

```js
  let origin;
  try {
    origin = await siteOrigin();
  } catch (err) {
    problems.push(err.message);          // line 769 -- unprefixed
    return problems;
  }
```

`siteOrigin()` (line 735) does `await readFile(ASTRO_CONFIG_PATH, 'utf8')`
before its own `throw new Error('check-dist: could not find \`site\` ...')`.
Reproduced in the clone by running the script against a fixture with no
`astro.config.mjs`: every emitted line carries `check-dist: ` except one, which
reads `ENOENT: no such file or directory, open '/tmp/.../astro.config.mjs'`.

The comment above that guard (lines 762-767) claims the treatment is "the same
... `scripts/check-headers.mjs` applies". `scripts/check-headers.mjs:270-286`
does carry a top-level wrapper -- `main()` awaits `run()` inside a `try` and
prints `check-headers: unhandled error: ${err.message}` on a throw -- and
`scripts/check-dist.mjs` has no counterpart, so the claim is currently false.

### `test/check-dist.test.ts` (109 lines)

Two tests spawn a copy of the script against an `mkdtemp` fixture. The fixture
(`makeFixture`, line 29) carries `scripts/check-dist.mjs`, `src/lib`, an
`astro.config.mjs` with a `site`, empty `src/content/journal` and
`src/content/adr`, one hashed asset and one `dist/index.html`. It deliberately
has no `package.json`, no `dist/sitemap-index.xml` and no `dist/og.png`.

The mismatch test (line 61) asserts with `assert.match`, so it proves reach. The
control (line 76) ends with only:

```js
    assert.doesNotMatch(result.stderr, new RegExp(`x\\.${realHash8}\\.css.*does not match`));
    assert.doesNotMatch(result.stderr, /does not exist under dist/);
```

Running the script against exactly that fixture in the clone emits thirteen
problem lines, the last of which is
`check-dist: dist/sitemap-index.xml does not exist`. That line is produced by
`checkSitemap()`, which runs strictly after `checkHashedSubresources()`, so its
presence is a positive proof of reach -- and it is absent the moment anything
upstream throws, which is the vacuity mode the finding describes.

### `scripts/vendor-assets.mjs` -- `nonEmptyHashedFile()` (line 564)

```js
async function nonEmptyHashedFile(p) {
  if (!(await nonEmptyFile(p))) return false;
  const bytes = await readFile(p);
  return hashMismatch(path.basename(p), bytes) === null;
}
```

`hashMismatch()` (`src/lib/content-hash.ts:38`) returns `null` when
`hashInName()` is `null` -- "nothing to check". Verified directly in the clone:
`hashInName('site.css')` is `null` and `hashMismatch('site.css', <bytes>)` is
`null`. `verifyExistingTree()` (line 590) calls `nonEmptyHashedFile()` for every
`manifest.styles` entry (line 601), every `manifest.preload` value (line 604)
and every `url()` in the generated `fonts.css` (line 635). An entry that lost its
hash therefore passes all three, and the offline branch of `main()` (line 716)
prints `vendor: existing tree ... is complete and valid; continuing offline.` and
returns 0. `src/data/assets.json`'s `styles[4]` is `/styles/site.aa80926c.css`
today; `public/styles/` is gitignored and regenerated by `copySiteCss()` through
`emit()`, which always writes `${baseName}.${hash}${ext}` (line 59).

`scripts/check-dist.mjs`'s `checkHashedSubresources()` (line 491) does not
backstop this: it runs post-build against `dist/`, its unhashed-reference
message is a different string ("with no 8-hex content hash before its
extension"), and the offline vendor run would already have exited 0.

## Proposed solution

Six independent edits, ordered so the later proofs can assert on the earlier
fixes. Nothing is shared between them except the ordering of A2 before A1.

### 1. A2 -- prefix and wrapper in `scripts/check-dist.mjs`

Two changes in one file.

The push at line 769 becomes:

```js
    problems.push(err.message.startsWith('check-dist:') ? err.message : `check-dist: ${err.message}`);
```

The ternary is what keeps `siteOrigin()`'s own already-prefixed throw from
reading `check-dist: check-dist: could not find ...`.

The module tail takes the shape `scripts/check-headers.mjs:270-286` already uses:
the existing `async function main()` at line 830 is renamed to
`async function run()`, and a new wrapper is added above the call site:

```js
/**
 * B3a (issue #71, A2): wraps the whole run so any residual throw -- from a
 * helper this file does not yet guard, or from a future edit that
 * reintroduces one -- becomes one final problem line and a non-zero exit,
 * rather than an uncaught rejection that discards the accumulated report.
 * Same shape as scripts/check-headers.mjs's main()/run() split.
 */
async function main() {
  try {
    await run();
  } catch (err) {
    console.error(`check-dist: unhandled error: ${err.message}`);
    process.exitCode = 1;
  }
}

await main();
```

`await main();` stays unconditional -- no `isEntryPoint()`. Every existing caller
(`package.json`'s `build`, the tests that spawn it) is unaffected, and the
prefix invariant now holds for the catch-all line too.

### 2. A1 -- make the control test prove reach, and prove that it can go red

The control at `test/check-dist.test.ts:76` gains a third assertion before the
two `doesNotMatch` lines:

```js
    assert.match(result.stderr, /check-dist: dist\/sitemap-index\.xml does not exist/);
```

Then a new mutation test proves that assertion is load-bearing. It reuses the
fixture builder, but patches the copied script on the way in:

```js
const UPSTREAM_ANCHOR = 'problems.push(...checkNavigationState(html, rel));';

async function makeFixtureWithUpstreamThrow(assetBytes: Buffer): Promise<string> {
  const tmp = await makeFixture(assetBytes);
  const scriptPath = path.join(tmp, 'scripts/check-dist.mjs');
  const source = await readFile(scriptPath, 'utf8');
  assert.equal(
    source.split(UPSTREAM_ANCHOR).length - 1,
    1,
    'expected exactly one upstream anchor to inject a throw at',
  );
  await writeFile(
    scriptPath,
    source.replace(UPSTREAM_ANCHOR, "throw new Error('injected upstream failure');"),
    'utf8',
  );
  return tmp;
}
```

The test asserts non-zero exit, stderr matching
`/check-dist: unhandled error: injected upstream failure/` (the A2 wrapper's
line), and `assert.doesNotMatch(result.stderr, /sitemap-index\.xml does not exist/)`
-- the reach marker is gone, so the control's new `assert.match` would fail
against this mutant. That is the demonstration the issue asks for, committed
rather than performed once during review. The equality assertion on the anchor
count is what stops the injection itself from becoming the next vacuous guard.

Against the pre-A2 code the same mutant dies with an uncaught rejection and a
stack trace; the reach marker is absent either way, so the test proves the A1
point in both worlds and additionally pins A2's wrapper message.

### 3. A2 proofs -- prefix invariant

Two more tests in `test/check-dist.test.ts`, each with its own fixture variant
(the existing `makeFixture` gains an options argument, or two small builders are
added -- either is acceptable; the tasks assume an options argument
`{ astroConfig: 'site' | 'no-site' | 'missing' }` defaulting to `'site'`):

- Fixture with `astroConfig: 'missing'`: split stderr on newlines, drop empty
  lines, and assert every line starts with `check-dist: `. The failure message
  names the first offending line, so the pre-fix run reports the actual
  `ENOENT: ...` text rather than `false !== true`.
- Fixture with `astroConfig: 'no-site'` (a config file that exports an object
  with no `site` key): assert stderr matches
  `/check-dist: could not find `site` in astro\.config\.mjs/` and
  `assert.doesNotMatch(result.stderr, /check-dist: check-dist:/)`.

### 4. A3 -- reject unhashed names at the caller

`scripts/vendor-assets.mjs:41` extends its import:

```js
import { contentHash8, hashInName, hashMismatch } from '../src/lib/content-hash.ts';
```

and `nonEmptyHashedFile()` becomes:

```js
async function nonEmptyHashedFile(p) {
  if (!(await nonEmptyFile(p))) return false;
  const name = path.basename(p);
  // A name with no hash segment at all is not "checked and fine" -- it is
  // unpinnable. hashMismatch() returns null for it ("nothing to check"), a
  // contract that is correct for the two post-build checkers that meet
  // unhashed names legitimately, so the rejection belongs here.
  if (hashInName(name) === null) return false;
  const bytes = await readFile(p);
  return hashMismatch(name, bytes) === null;
}
```

`src/lib/content-hash.ts` is untouched. The three call sites (lines 601, 604,
635) need no change: every manifest entry, preload href and `fonts.css` `url()`
in the committed tree is hashed today, which the existing
`control: ... exits 0 under VENDOR_FORCE_OFFLINE=1` test keeps proving.

The named mutant goes into `test/vendor-assets.test.ts`, alongside the two that
already live there and using the same `makeTreeCopy()` / `runVendorOffline()`
helpers:

```js
async function unhashSiteCssEntry(tmp: string): Promise<void> {
  const manifestPath = path.join(tmp, 'src/data/assets.json');
  const manifest = JSON.parse(await readFile(manifestPath, 'utf8'));
  manifest.styles[4] = '/styles/site.css';
  await writeFile(manifestPath, `${JSON.stringify(manifest, null, 2)}\n`, 'utf8');
  await mkdir(path.join(tmp, 'public/styles'), { recursive: true });
  await writeFile(path.join(tmp, 'public/styles/site.css'), 'body { color: red }\n', 'utf8');
}
```

Exit 1 and `/vendor: no valid existing tree/` after the fix; exit 0 before it.

### 5. B1 -- word boundary

One line in `test/work.test.ts:55`:

```js
    if (new RegExp(`\\b${escapeRegExp(literal)}\\b`).test(source)) {
```

`\b` holds at both ends of every one of the seven literals, including the two
with an internal space (`design tokens`, `upstream fork`) -- the boundary is
evaluated at `d`/`s` and `u`/`k`. Two new tests pin the change: `'<!-- Golang and
Google are mentioned -->'` reports nothing, `'<p>Go is a language</p>'` reports
`"Go"`. The existing D2a/D2b tests are re-run unchanged and are the proof the
boundary did not weaken the guard -- the frontmatter case `'  - Go\n'` still
matches (`\b` holds after a space and before a newline), as do the regex
terminator, element text and template interpolation cases.

### 6. C1 and D1 -- correct by inspection

`test/entry-point.test.ts` lines 1-2 are rewritten to name all three scripts and
to say which one carries the CI weight:

```
// B1: scripts/check-contrast.mjs, scripts/check-links.mjs and
// scripts/check-headers.mjs each carry an isEntryPoint() that must keep its
// hybrid form -- scripts/check-headers.mjs most of all: it is the sole
// assertion of .github/workflows/build.yml's `build` job, so an isEntryPoint()
// that silently returned false there would make that whole job vacuous.
```

`test/fonts.test.ts` gets one helper near `collectFaceRules()`:

```js
/** Composite family/weight key. `|` cannot occur in a CSS font-family name,
 * so the key stays unambiguous -- and unlike the raw NUL byte this used to
 * carry, it does not make the whole file read as binary to grep. */
function faceKey(family: string, weight: string | number): string {
  return `${family}|${weight}`;
}
```

and all six sites (lines 297, 305, 321, 329, 339, 347) call it. Both halves of
each pair must change together -- a construction site left on NUL while its
lookup moves to `|` turns those assertions into silent failures.

The new `test/source-hygiene.test.ts` walks `test/`, `scripts/` and `src/`,
reads each file as a `Buffer`, and asserts `buf.indexOf(0)` is `-1`, naming the
file and offset on failure. It is added to `package.json`'s `test` script.

## Alternatives

**Fix A3 inside `hashMismatch()`.** Make it return a message when the name
carries no hash. Dropped: `scripts/check-dist.mjs`'s `checkHashedSubresources()`
and `scripts/check-headers.mjs` both meet names that legitimately have no hash
(`checkHashedSubresources()` already reports that case with its own, different
message before it ever calls `hashMismatch()`), and `test/cache.test.ts` imports
the same predicate. A shared lenient contract with one strict caller is the
smaller change and the one the finding prescribes.

**Prove A1 by a manual mutation during review instead of a committed test.**
That is literally what the issue's wording suggests ("make an upstream stage
throw and show the test goes red"). Dropped because `AGENTS.md` rules out
acceptance criteria that can only be satisfied in the pull request body, and
because a one-time demonstration decays: the committed mutant keeps proving the
reach assertion is load-bearing on every run, which is the same posture
`test/vendor-assets.test.ts`'s two existing `mutant:` tests already take.

**Add an `isEntryPoint()` guard to `scripts/check-dist.mjs` while adding the
wrapper.** Tempting, since A1's own header comment calls out its absence.
Dropped: the tests spawn the script as a CLI, so the guard buys nothing here,
and it would put `scripts/check-dist.mjs` into an ambiguous relationship with
`test/entry-point.test.ts`'s `FILES` list in the same cycle that C1 is fixing
that file's header to name exactly three scripts. Two cycles' worth of intent in
one diff.

**Use a different D1 separator -- the NUL written as a `\x00` escape, or `\x1f`.**
The escape form keeps the key bytes identical and fixes grep, but it leaves a
control character in a string that a future copy-paste can turn back into a raw
byte. `|` is printable, cannot occur in a CSS `font-family` name, and survives
any editor round-trip. `\x1f` shares the escape form's fragility with none of
its compatibility benefit, since no key is persisted anywhere.

## Platform impact

**Rendered output.** One change, from C3: `/work/`'s `mctl-design` card no
longer names version `0.5.0` in either language. Everything else below still
holds.

**Migrations.** None. No content schema, no data file, no other rendered output
changes. `src/data/assets.json` is read but never rewritten by this cycle.

**Backward compatibility.** `scripts/check-dist.mjs` gains one new stderr line
shape (`check-dist: unhandled error: ...`) that only appears on a throw that
previously produced a stack trace and no report -- strictly better output. The
`check-dist: ` prefix invariant becomes total, which is what any log grep on
that prefix already assumed. `scripts/vendor-assets.mjs` becomes stricter, but
only against a tree that is already broken: every committed href is hashed today,
proven by the existing offline control test and by `test/cache.test.ts`'s walk
over `public/assets/`.

**Resource impact.** Three new spawn-based tests in `test/check-dist.test.ts`
and one in `test/vendor-assets.test.ts`, each on the order of a second; the
`test/source-hygiene.test.ts` walk reads roughly two hundred kilobytes. CI wall
time moves by a few seconds.

**Risks and mitigations.**

- *The A1 mutation test's anchor drifts.* `problems.push(...checkNavigationState(html, rel));`
  is a literal string in a source file a later cycle may rename. Mitigated by the
  `assert.equal(count, 1)` on the anchor before substitution: the test fails with
  "expected exactly one upstream anchor" rather than passing vacuously, which is
  the whole point of the finding.
- *The A2 rename (`main` to `run`) breaks a caller.* Nothing imports
  `scripts/check-dist.mjs`; it has no export and no `isEntryPoint()`. The only
  entry is the module-scope call, which is updated in the same edit. Mitigated by
  `npm run build`, which runs the script for real.
- *A3 rejects something legitimate.* The only names it now refuses are ones with
  no hash segment. The three `nonEmptyFile()` call sites that legitimately handle
  unhashed files -- the per-family licence texts (line 646) and the two
  build-only Onest TTFs (line 651) -- go through `nonEmptyFile()`, not
  `nonEmptyHashedFile()`, and are untouched. The existing offline control test is
  the regression guard.
- *D1's partial application.* Changing the three `new Set(...)` sites without the
  three `.has(...)` sites would make those assertions fail on every run (loudly,
  not silently) -- but the reverse pairing in the negative assertion at line 329
  (`!facePairKeys.has(...)`) would pass for the wrong reason. Mitigated by routing
  all six through the single `faceKey()` helper, so the separator exists once.
- *`test/source-hygiene.test.ts` false-positives on a legitimately binary file.*
  It scans only `test/`, `scripts/` and `src/`, none of which hold binaries today
  (`scripts/fonts/*.ttf` is the one risk -- the walk must skip that directory or
  filter to a text-extension allowlist of `.ts`, `.mjs`, `.astro`, `.css`, `.md`,
  `.json`). The tasks name the allowlist explicitly.
