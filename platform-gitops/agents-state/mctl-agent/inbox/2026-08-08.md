## Top-3 (for spec-writer)

### 1. argo-workflows-cve-patch: Patch Argo Workflows for auth-bypass, info-disclosure and plaintext-credential CVEs
**Category:** security
**Impact:** 5
**Effort:** 2
**Rationale:** Three distinct CVEs (info disclosure via arbitrary bearer token, `templateReferencing: Strict` authz bypass enabling hostNetwork/serviceAccount escalation, and plaintext artifact-repository credentials) plus an incomplete-fix GHSA all hit `argoproj/argo-workflows`, which is an explicit dependency per `context/architecture.md` and is the engine behind the `cwft-rotate-github-token` CronWorkflow that rotates mctl-agent's GitHub App token every 30 minutes. A compromised or vulnerable Workflows controller directly threatens the credential mctl-agent uses to open fix PRs, making this the highest-impact, best-architecturally-fit finding today. Fix is a version bump to >=4.0.5/3.7.14 (patched line), not a code change in mctl-agent itself, so effort is low. No labs-tenant memory impact — this is a control-plane component upgrade, not a new dependency in the mctl-agent pod.
**Source:** CVE-2026-28229, CVE-2026-42296, CVE-2026-42295, GHSA-3775-99mw-8rp4 (Source: cve); argo-workflows v4.0.8 release note (Source: github releases); architecture.md "Argo Workflows CRDs" dependency + "GitHub App ... rotated every 30 minutes via CronWorkflow cwft-rotate-github-token".

### 2. poller-401-incident-gap: Fix recurring poller 401 (invalid GitHub token) and close the logs-vs-incidents monitoring gap
**Category:** performance
**Impact:** 4
**Effort:** 2
**Rationale:** The poller has been failing every ~5 minutes for at least an hour with `invalid GitHub token: token rejected by GitHub (HTTP 401)`, which is also blocking orphan-service pruning (`service inventory unknown`) — a core self-healing loop is degraded. Despite the recurrence, `mctl_list_incidents` shows zero matching incidents, meaning this failure mode is currently invisible to on-call. This is a genuine reliability + observability defect directly inside mctl-agent's own polling/token-refresh path (not a third-party library), so it scores high on platform impact with low effort (fix the stale-token consumption path and add an alert rule tying repeated 401s to a ticket).
**Source:** "Recurring poller error", "Related resolve-alert failure", "Repeated WARN" (Source: mctl metrics); "No active incidents" (Source: mctl incidents).

### 3. go-runtime-cve-upgrade: Bump Go toolchain baseline to close the HTTP/2 SETTINGS-frame DoS (CVE-2026-33814) and other in-scope runtime CVEs
**Category:** security
**Impact:** 4
**Effort:** 3
**Rationale:** mctl-agent is an exposed Go HTTP service (AlertManager webhook, Telegram webhook, REST API, MCP JSON-RPC endpoint all served over `net/http`/chi), and CVE-2026-33814 is a real DoS in `net/http`'s HTTP/2 transport — directly in mctl-agent's runtime attack surface. The current baseline (Go 1.24 per architecture.md) is several minor releases behind the patched lines (1.25.10 / 1.26.3), so this single upgrade also sweeps up any other applicable point-release fixes. Effort is moderate (toolchain bump + regression pass across the skill pipeline and chi router), and a language-runtime patch does not add memory-hungry dependencies, so it carries no labs-tenant risk (mctl-agent runs only in tenant `admins` regardless).
**Source:** CVE-2026-33814 (Source: cve); "golang/go ... Architecture.md baseline is Go 1.24 — appears multiple minor versions behind" (Source: github releases); architecture.md tech stack "Go 1.24".
