## Top-3 (for spec-writer)

### 1. x-net-html-cve-audit: Audit and patch transitive golang.org/x/net exposure
**Category:** security
**Impact:** 3
**Effort:** 1
**Rationale:** New x/net HTML CVEs appeared on 4 Nov and no existing proposal covers x/net (only x-crypto-ssh audits exist). The spec should check via `go mod why` / `govulncheck` whether x/net/html is reachable, and bump x/net if so. Build-time change only; no memory impact on `labs`.
**Source:** cve section, CVE-2026-97045 / CVE-2026-78661.

### 2. govulncheck-ci-gate: Add a govulncheck gate to CI and a scheduled scan
**Category:** security
**Impact:** 4
**Effort:** 2
**Rationale:** Nearly every daily run re-proposes the same dependency bump (dozens of near-duplicate folders). A reachability-aware `govulncheck` gate in CI plus a weekly scheduled scan catches vulnerable dependencies automatically and fails builds on reachable ones. Existing proposals mention govulncheck only as a task inside individual bumps.
**Source:** recurring Go/chi/sqlite CVE findings across the 11-07, 11-14 and 11-21 inboxes.

### 3. automated-dependency-update-prs: Automate dependency update PRs (Renovate/Dependabot) with grouping
**Category:** refactor
**Impact:** 3
**Effort:** 2
**Rationale:** Version-bump proposals (go-github, chi, anthropic-sdk, sqlite) keep being regenerated because versions are manual. Grouped automated PRs with CI as the safety net would remove this toil, with major bumps (go-github v68 to v93) kept as manual and labelled. No runtime impact.
**Source:** go-github v93.0.0, anthropic-sdk-go v2.13.0, chi v5.5.0 releases; large number of existing bump-* folders.
