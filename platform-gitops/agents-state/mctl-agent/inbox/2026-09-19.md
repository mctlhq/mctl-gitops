## Top-3 (for spec-writer)

### 1. chi-redirect-cve-boundary-check: Bump go-chi/chi to v5.3.2 and verify open-redirect CVE boundary before upgrading
**Category:** security
**Impact:** 3
**Effort:** 2
**Rationale:** chi/v5 is the router for every mctl-agent HTTP surface (AlertManager webhook, Telegram webhook, REST API, MCP endpoint), so router-level fixes apply directly to us. Our current 5.2.1 sits just below the affected range (>=5.2.2) of the `RedirectSlashes` open-redirect CVE-2025-69725, so a naive bump to 5.3.2 must include auditing whether we use `RedirectSlashes` and applying the fix, otherwise the "upgrade" would move us into the vulnerable range. 5.3.2 also fixes a wildcard-route construction panic and a Mount()/Route() handler-collision bug relevant to our multi-route tree.
**Source:** https://github.com/go-chi/chi/releases/latest (v5.3.2); https://github.com/advisories/GHSA-4h76-926q-wxxw (CVE-2025-69725)

### 2. x-crypto-ssh-transitive-audit: Audit dependency tree for transitive golang.org/x/crypto/ssh exposure
**Category:** security
**Impact:** 4
**Effort:** 1
**Rationale:** Six CVEs were disclosed against golang.org/x/crypto on 2026-09-15, including an unauthenticated CPU-exhaustion vector (CVE-2026-39829, RSA/DSA parsing without key-size limits) and an unbounded server-memory-growth issue (CVE-2026-39827). We do not list x/crypto directly, but it could be pulled transitively via chi, go-github, or anthropic-sdk-go; a `go mod graph` / `go list -m all` check is nearly free and either rules this out or surfaces a real, high-severity exposure worth patching immediately.
**Source:** https://www.securityfocus.com/advisory/ROOT-APP-GOBINARY-CVE-2026-46597 (representative of the CVE-2026-398xx/399xx cluster)

### 3. anthropic-sdk-compact-before-next-turn: Adopt anthropic-sdk-go v1.74.0's CompactBeforeNextTurn() in the diagnose loop
**Category:** performance
**Impact:** 3
**Effort:** 2
**Rationale:** The diagnose phase (skill match → diagnose → fix, incl. the LLMDiagnosis fallback skill) drives multi-turn tool calls against the Anthropic API; CompactBeforeNextTurn() can trim growing tool-call context between turns, reducing token usage, latency, and API cost with no breaking changes in this release. Low-risk incremental SDK bump that improves an existing, frequently-hit code path rather than adding new surface area.
**Source:** https://github.com/anthropics/anthropic-sdk-go/releases/latest (v1.74.0, released 2026-09-18)
