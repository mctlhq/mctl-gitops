## Top-3 (for spec-writer)

### 1. go-toolchain-bump: Move build toolchain from Go 1.24 to the current patched Go release
**Category:** security
**Impact:** 5
**Effort:** 2
**Rationale:** The service is pinned to Go 1.24 and ships a public webhook endpoint (`agent.mctl.ai`) that uses net/http, x/net and crypto/x509. Open stdlib/x/net CVEs include CVE-2026-78661 (7.5 High) and the x509 distrust fix CVE-2026-111943, and a toolchain bump is the only remedy for stdlib fixes. UNVERIFIED: the target version "Go 1.26.10" comes only from Alertmanager release notes (golang/go releases page returned nothing), and the x/net CVE affected-version ranges are not confirmed. The spec must first confirm the exact latest patch on go.dev/dl and whether 1.24 is affected, and run `govulncheck` against the current binary. Memory impact on `labs` is nil (the agent runs in `admins`); still check RSS after the bump.
**Source:** Inbox, cve section: "Go stdlib / x/net CVEs", "Go crypto/x509 CVE-2026-111943"; github releases: alertmanager v0.34.2.

### 2. chi-upgrade-and-middleware-audit: Upgrade chi 5.2.1 to 5.5.0 and audit RealIP / RedirectSlashes usage
**Category:** security
**Impact:** 3
**Effort:** 2
**Rationale:** chi serves the AlertManager and Telegram webhooks, so router/middleware bugs are directly exposed. The Go vuln list shows X-Forwarded-For spoofing in RealIP and an open redirect in RedirectSlashes; UNVERIFIED: advisory dates and fixed versions are unknown, and they may already be fixed in 5.2.1 or earlier. The spec's first task is to check whether the code uses either middleware (trusting spoofed IPs would matter if rate limiting or auth allow-lists key on client IP) and to confirm the fixed-in versions with `govulncheck`. The 5.5.0 changes (Retry-After rounding, SupressNotFound context handling) are low-risk but need a regression test run on the API routes.
**Source:** Inbox: "go-chi/chi v5.5.0" release; cve section "go-chi/chi/v5 advisories".

### 3. modernc-sqlite-upgrade: Upgrade modernc.org/sqlite 1.34 to 1.61.x with context-aware busy timeout
**Category:** performance
**Impact:** 3
**Effort:** 3
**Rationale:** The pin is about 27 minor versions behind and carries many SQLite engine updates (to 3.53.4), which also picks up upstream SQLite security fixes. v1.61.0 stops busy-timeout waits when the caller's context is cancelled, which helps the ticket pipeline and webhook handlers avoid hanging on a locked DB. This keeps the accepted single-pod SQLite design (no Postgres). No CVE was found, so priority is below the first two; the spec needs a migration test on a copy of the tickets and skill-metrics DB, and a memory check before rollout since the pure-Go engine's footprint can change.
**Source:** Inbox: "modernc.org/sqlite v1.61.1" (tags v1.61.0, v1.58.0).
