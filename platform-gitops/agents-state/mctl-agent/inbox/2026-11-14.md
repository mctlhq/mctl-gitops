## Top-3 (for spec-writer)

### 1. go-1274-nethttp-maxbytes-patch: Move toolchain to Go 1.27.4 / 1.26.11 for the net/http MaxBytesReader crash fix
**Category:** security
**Impact:** 4
**Effort:** 1
**Rationale:** CVE-2026-97054 / GO-2026-6859 is a remotely triggerable HTTP/1 server crash in net/http, and mctl-agent exposes public webhook endpoints (`/api/v1/alerts`, `/api/v1/telegram`, `/mcp`) on chi. The spec should pin the exact patched patch release, since sources conflict on whether 1.26.11 fully fixes it. It should also require a `govulncheck` gate. The cgo-related CVEs are low risk because modernc sqlite is pure Go (no CGO). The bump is a build-time change with no runtime memory growth, so it is safe for `labs`.
**Source:** cve section, "Go 1.27.4 / 1.26.11 security release (10 Nov)"; https://securityonline.info/go-security-fixes-1-27-4/
**Overlap:** Overlaps existing folders go-toolchain-bump, bump-go-toolchain, go-toolchain-security-upgrade, go-runtime-patch and go-toolchain-1263-patch. No existing folder was seen that targets 1.27.4/1.26.11 or CVE-2026-97054, so the spec-writer should cite those folders and focus only on the delta. Note that architecture.md still says Go 1.24, so the real baseline must be checked first.

### 2. chi-suppressnotfound-redirectslashes-audit: Upgrade chi to 5.5.0 and remove or guard the vulnerable middlewares
**Category:** security
**Impact:** 4
**Effort:** 2
**Rationale:** The pin 5.2.1 is below the fixes for CVE-2026-114437 (5.4.0) and CVE-2026-118681 (`SupressNotFound` auth bypass, fixed in 5.5.0). The RealIP spoofing advisories (GO-2026-5774/5775/5777) matter if rate limiting or audit logging trusts client IP. CVE-2026-122132 (`RedirectSlashes` open redirect, tab in path) has no fix even in 5.5.0, so the spec must grep for `RedirectSlashes`, `SupressNotFound` and `RealIP` and drop, replace or guard whichever is used. Moving from 5.2.1 to 5.5.0 is a small, low-memory change.
**Source:** cve section, CVE-2026-118681 (https://osv.dev/vulnerability/CVE-2026-118681), CVE-2026-122132 (https://vuldb.com/vuln/431218), GO-2026-5774/5775/5777
**Overlap:** Heavy overlap with chi-upgrade-and-middleware-audit, bump-chi, chi-v5-security-upgrade, chi-open-redirect and chi-redirect-cve-boundary-check. The distinct part is the unfixed-in-5.5.0 RedirectSlashes handling plus the new auth-bypass CVE. If chi-open-redirect already covers the redirect guard, the spec-writer should reference it rather than duplicate it.

### 3. modernc-sqlite-v1620-wal-hardening: Upgrade modernc.org/sqlite 1.34 to v1.62.0 (SQLite 3.54.1) with WAL and migration validation
**Category:** security
**Impact:** 3
**Effort:** 3
**Rationale:** The pin 1.34 is about 28 minor versions behind and misses CVE-2026-119591 (C-stack exhaustion on a crafted view, fixed before 3.54.0) and CVE-2026-119375 (uninitialised page-cache bytes from a WAL page-size mismatch). Exposure is limited because the tickets DB is local and single-pod, but a crafted tickets or skill-metrics DB file or restored PVC is a plausible vector. The spec should include a snapshot, a restore test on a copy of the existing DB, and a measurement of RSS before and after. v1.62.0 may increase binary size and memory, so `admins` is fine but any shared tooling in `labs` must be checked first (flag as risky if it is used there).
**Source:** cve section, CVE-2026-119591 (https://github.com/giantswarm/mcp-capi/issues/371) and CVE-2026-119375; release tag https://gitlab.com/cznic/sqlite/-/tags
**Overlap:** Overlaps modernc-sqlite-upgrade, sqlite-upgrade, sqlite-v150-upgrade, sqlite-cve-patch, sqlite-stack-dependency-update and sqlite-zipfile-cve-audit. The delta is v1.62.0 / SQLite 3.54.1 and the two new CVEs, with WAL-specific validation.
