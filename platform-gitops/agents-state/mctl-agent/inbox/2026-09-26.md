## Top-3 (for spec-writer)

### 1. anthropic-sdk-v175-compaction-fix: Upgrade anthropic-sdk-go to v1.75.0 for tool-runner compaction fix
**Category:** performance
**Impact:** 4
**Effort:** 2
**Rationale:** v1.75.0 removes reply-only params from the tool runner's compaction request, directly addressing the `CompactBeforeNextTurn()` risk flagged last cycle, and also makes `AddTools()` take effect immediately and preserves extra fields on open-object param unmarshalling — all of which bear directly on the correctness of the diagnose-phase client. It's a concrete upstream fix for an issue we already identified, low effort (dependency bump + regression test of the compaction path), and does not increase memory footprint. Note: mctl-agent runs only in tenant `admins`, so the `labs` memory constraint does not apply here.
**Source:** github releases — anthropic-sdk-go v1.75.0, https://github.com/anthropics/anthropic-sdk-go/releases/latest

### 2. x-crypto-ssh-transitive-audit-v2: Re-verify x/crypto/ssh transitive exposure against the newly surfaced CVE-2026-39830
**Category:** security
**Impact:** 3
**Effort:** 2
**Rationale:** CVE-2026-39830 (malicious SSH peer floods an internal buffer with unsolicited global-request responses, stalling the connection's read loop) is new this cycle and adds to the six CVEs already tracked by the existing transitive-audit proposal. golang.org/x/crypto is not a direct dependency per architecture.md, so the actionable item is a `go mod graph`/`go mod why` check to confirm whether chi, go-github, or anthropic-sdk-go pull `x/crypto/ssh` transitively before deciding whether a forced bump is needed; this supersedes the prior audit with an updated CVE list rather than duplicating it outright.
**Source:** cve — CVE-2026-39830 (cluster reference), https://psirt.com/advisory/ROOT-APP-GOBINARY-CVE-2026-39831

### 3. chi-v532-mount-route-fix: Upgrade go-chi/chi to v5.3.2 for the Mount()/Route() handler-collision fix
**Category:** refactor
**Impact:** 3
**Effort:** 1
**Rationale:** v5.3.2 fixes a bug where `Mount()`/`Route()` handler collisions could silently drop a registered handler. mctl-agent mounts several routers on one chi instance (AlertManager webhook, Telegram webhook, REST API, MCP endpoint), so a silent route drop is a real availability risk for the alert-ingestion path. This is distinct from the already-tracked CVE-2025-69725 open-redirect proposal — this cycle's CVE search in fact clarifies the fix for that CVE landed in v5.2.4+, confirming our shipped v5.2.1 predates (and is unaffected by) the vulnerable range, so no new action is needed there. The Mount/Route fix is a separate, low-effort dependency bump.
**Source:** github releases — go-chi/chi v5.3.2, https://github.com/go-chi/chi/releases/latest
