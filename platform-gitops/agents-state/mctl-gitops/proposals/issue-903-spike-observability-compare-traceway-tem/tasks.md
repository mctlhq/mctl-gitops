## Rollback

Merging this PR changes no cluster state, so rollback is correspondingly
cheap. Three levels.

1. **Nothing to roll back at merge.** `otelCollector.backends` is `[]` and
   `otelCollector.eval.enabled` is `false`, so the rendered collector
   ConfigMap is identical to `main` — T1's golden-file comparison is the proof
   — and no Namespace, Application or NetworkPolicy is emitted. The only new
   in-cluster objects are the `otel-trace-fixture` ClusterWorkflowTemplate and
   its ConfigMap in `argo-workflows`, both inert: a registered template runs
   nothing until a workflow is submitted, and this PR adds no CronWorkflow.

2. **If the ADR or rubric is disputed after merge.** Amend rather than revert.
   The rubric is frozen on purpose; changing a weight after scores exist would
   be the failure mode it was merged to prevent, but no scores exist yet, so
   editing the weights in a follow-up PR before #1280 deploys anything is both
   legitimate and cheap. If the spike is abandoned entirely, the ADR is
   amended with an `Abandoned` status and the reason — not deleted — so the
   next attempt starts from the screen rather than from zero.

3. **Full revert.** `git revert` the PR. This removes the `backends` and
   `eval` keys, the two gated templates, the fixtures, the materializer, the
   emitter template, its ConfigMap, the tests and the CI steps, and restores
   the scalar-only exporter block. Safe at any time while
   `otelCollector.backends` is `[]` and `eval.enabled` is `false`. If #1280
   has already flipped either key, set them back first and let ArgoCD sync
   before reverting, otherwise the revert removes a template while values
   still reference it. Note that `otel-collector` runs with `selfHeal: true`,
   so a manual `kubectl edit` of the collector ConfigMap is reverted by ArgoCD
   and is never a valid rollback path — the values file is.

Not rolled back in any case: `docs/adr/`. Once created it stays, because its
existence is the thing that makes the next observability decision cheaper.
