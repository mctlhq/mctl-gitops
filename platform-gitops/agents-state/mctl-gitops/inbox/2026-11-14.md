### 1. argocd-repo-server-multi-cve-patch: Patch Argo CD to 3.3.15 / 3.4.10 / 3.5.4 within the current minor line
**Category:** security
**Impact:** 5
**Effort:** 3
**Rationale:** Four Critical and one High repo-server vulns are fixed together; Argo CD reconciles this whole repo, so a repo-server compromise exposes all repo credentials. Same-minor patch bump only (no major jump), staged admins first. Prior proposals (argocd-repo-server-hardening, argocd-serversidediff-*) covered other CVEs and do not include these IDs. Argo CD runs in admins; check labs quota for rolling restarts. IDs unverified against GHSA; spec-writer must confirm.
**Source:** cve section, osv.dev CVE-2026-113709.

### 2. argocd-repo-server-feature-lockdown: Disable unused Jsonnet/Kustomize-Helm/SSH-proxy repo-server features
**Category:** security
**Impact:** 4
**Effort:** 2
**Rationale:** Until patched, config mitigations reduce exposure: audit use of Jsonnet, kustomize `--enable-helm`, and SSH proxy repo settings, and disable what is unused. Also remains useful defense in depth after patching. No new pods, no labs memory impact.
**Source:** CVE-2026-113672, -113708, -113709, -55797.

### 3. argocd-repo-credential-rotation: Scope and rotate credentials reachable from repo-server
**Category:** security
**Impact:** 3
**Effort:** 3
**Rationale:** CVE-2026-113672 and -55797 expose repo-server-reachable credentials (SA tokens, deploy key `mctl-gitops-deploy-key`, Helm/OCI creds). Plan least-privilege scoping and rotation via Vault/ExternalSecrets after patching. Rotation must go through Vault, never hand-edited secrets.
**Source:** CVE-2026-113672, CVE-2026-55797.
