### 1. argo-rollouts-dashboard-unauth-mitigation: Interim mitigation for unauthenticated Argo Rollouts dashboard (CVE-2026-82277)
**Category:** security
**Impact:** 5
**Effort:** 2
**Rationale:** CVSS 9.8 — the Argo Rollouts dashboard (through our tracked v1.10.0) binds to all interfaces and lets an unauthenticated caller invoke mutating operations (PromoteRollout, AbortRollout, RestartRollout, SetRolloutImage, UndoRollout, RetryRollout) against any Rollout in the cluster, across both `admins` and `labs`. No upstream fix exists yet, so — mirroring how `argo-workflows-strict-mode-bypass-ghsa-3775` handled an unpatched issue last cycle — the actionable remediation is an interim mitigation (disable the dashboard or restrict it to authenticated/internal network access) plus a tracked follow-up for the eventual patched release. Confirmed non-duplicate: `argo-rollouts-v1-9-0-upgrade` addresses an unrelated BlueGreen analysis premature-success bug, not this dashboard-auth issue; no other Argo Rollouts security proposal exists.
**Source:** Argo Rollouts CVE-2026-82277 (CVSS 9.8), https://www.strix.ai/cve/CVE-2026-82277

### 2. argo-workflows-cve-93991-archive-authz: Confirm/patch ListArchivedWorkflows authorization bypass (CVE-2026-93991)
**Category:** security
**Impact:** 4
**Effort:** 2
**Rationale:** CVE-2026-93991 (CVSS 7.7) lets a caller bypass the cluster-scoped access review on `ListArchivedWorkflows` by supplying a `metadata.namespace` field selector, allowing archived-workflow data to be read across tenant boundaries (`admins` vs `labs`) — directly relevant since Argo Workflows drives every CronWorkflow/pipeline on this platform. It affects v4.1.0–4.1.3; our tracked latest v4.1.4 postdates disclosure, so the concrete task is to confirm the deployed version actually contains the fix (and pin/patch if not). Confirmed non-duplicate: the three existing Argo Workflows CVE proposals (`argo-workflows-cve-bundle-upgrade`, `argo-workflows-cve-patch`, `argo-workflows-cve-patch-v2`) all target CVE-2026-31892/28229/40886 — a different set of CVEs — and `argo-workflows-strict-mode-bypass-ghsa-3775` covers the unrelated GHSA-3775 podSpecPatch bypass (which is what today's recapped CVE-2026-42296 duplicates, not this one).
**Source:** Argo Workflows CVE-2026-93991 (CVSS 7.7), https://www.thehackerwire.com/vulnerability/CVE-2026-93991/

### 3. prometheus-v3-15-efficiency-upgrade: Upgrade Prometheus to v3.15.0 for scrape-compression and SD efficiency gains
**Category:** performance
**Impact:** 3
**Effort:** 2
**Rationale:** v3.15.0 adds zstd scrape-response compression and AWS SD efficiency improvements on top of the already-latest-tracked line, which reduces Prometheus's network/CPU overhead — a genuine, low-risk performance win that works *in favor of* the `labs` tenant's memory/CPU pressure (currently ~83% CPU / ~70% memory quota) rather than against it, unlike most other findings this cycle which are pure security patches. Confirmed non-duplicate: `prometheus-security-patch` only targets v3.11.3 for three specific CVEs (Azure AD credential exposure, snappy DoS, heatmap XSS — which subsume today's recapped CVE-2026-40179/CVE-2026-42151 and are already fixed by our tracked v3.15.0 line); no existing proposal covers the newer v3.15.0 efficiency features.
**Source:** Prometheus v3.15.0 release notes, https://github.com/prometheus/prometheus/releases/latest
