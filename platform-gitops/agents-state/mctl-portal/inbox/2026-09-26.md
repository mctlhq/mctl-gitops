## Source: cve
- **Backstage v1.55.2 changelog line "normalize TechDocs Markdown extension configuration"** — logged here as a possible security-adjacent change (not yet confirmed as a formal CVE fix) since it touches the same TechDocs markdown-extensions surface implicated in CVE-2026-88064; analyst should verify against the Backstage security advisory list whether this is tied to a CVE or a plain bugfix.

- **CVE-2026-29185 — Backstage SCM URL path traversal via built-in integration token (new finding this cycle)** — encoded path-traversal sequences in SCM URLs (GitHub, Bitbucket Server, Bitbucket Cloud integrations) can redirect integration API requests to unintended provider endpoints using the server-side integration credentials; affects any instance using SCM integrations with scaffolder or similar features accepting user-provided SCM URLs. Fixed in `@backstage/integration` 1.20.1+. mctl-portal uses GitHub integration and scaffolder. https://advisories.gitlab.com/pkg/npm/@backstage/integration/CVE-2026-29185/
- **CVE-2026-32235 — Backstage plugin-auth-backend OAuth redirect-URI allowlist bypass (new finding this cycle)** — affects the experimental OIDC provider; a crafted redirect URI can pass allowlist validation while resolving to an attacker-controlled host, allowing authorization-code theft on user consent. Fixed in 0.27.1+. Relevance to mctl-portal unclear — architecture.md lists Dex JWT via ops.mctl.me/api/dex as the SSO mechanism, not the experimental OIDC provider; analyst to confirm whether that flag is enabled. https://advisories.gitlab.com/pkg/npm/@backstage/plugin-auth-backend/CVE-2026-32235/
- **CVE-2026-32236 — Backstage plugin-auth-backend SSRF in experimental CIMD metadata fetch (new finding this cycle)** — SSRF in the experimental `auth.experimentalClientIdMetadataDocuments.enabled` flag (off by default): private-IP validation is applied to the initial client_id hostname but not after HTTP redirects; attacker cannot read the response body or control headers/method. https://advisories.gitlab.com/npm/@backstage/plugin-auth-backend/CVE-2026-32236/
- **CVE-2026-29184 — Backstage scaffolder log redaction bypass (new finding this cycle)** — a malicious scaffolder template can bypass log redaction to exfiltrate secrets passed through task event logs; fixed in `@backstage/plugin-scaffolder-backend` 3.1.4+. Directly relevant: scaffolder is our tenant-onboarding path (per architecture.md), which handles secrets/credentials during provisioning. https://advisories.gitlab.com/pkg/npm/@backstage/plugin-scaffolder-backend/CVE-2026-29184
- **CVE-2026-24046 — Backstage scaffolder symlink path traversal (new finding this cycle)** — multiple scaffolder actions and archive-extraction utilities vulnerable to symlink-based path traversal; an attacker able to create/execute scaffolder templates could read arbitrary files via `debug:log`, delete arbitrary files via `fs:delete`, or write outside the workspace via malicious symlinks in extracted archives. Directly relevant: scaffolder is actively used for tenant onboarding into mctl-gitops. https://advisories.gitlab.com/pkg/npm/@backstage/plugin-scaffolder-backend/CVE-2026-24046/
