## Top-3 (for spec-writer)

### 1. backstage-backend-defaults-ssrf-fix: Patch Backstage backend-defaults SSRF (CVE-2026-24048)
**Category:** security
**Impact:** 5
**Effort:** 2
**Rationale:** `@backstage/backend-defaults`'s FetchUrlReader follows redirects without re-checking the `backend.reading.allow` allowlist, allowing an allowed host to redirect requests to internal/sensitive URLs — a real SSRF risk given mctl-portal's backend does authenticated fetches (proxy plugin, TechDocs, scaffolder templates) against external and internal hosts. This is a patch-level dependency bump (backend-defaults 0.12.2/0.13.2/0.14.1/0.15.0, reachable via the already-available Backstage 1.54.6 train), not a major version jump, so it does not conflict with ADR 0001's "no major bump on release day" rule. Runs in tenant `admins`; no measurable memory increase expected, so it does not touch the `labs` memory-limit concern.
**Source:** CVE-2026-24048, https://www.sentinelone.com/vulnerability-database/cve-2026-24048/ (inbox `## Source: cve`). Bundling note: Backstage v1.54.4–v1.54.6 releases (28/25/24 Aug) also carry scaffolder/catalog validation and permission-handling fixes relevant to our onboarding flow (inbox `## Source: github releases`).

### 2. nodejs-lts-security-patch: Bump Node.js 22.x/24.x to latest patched LTS
**Category:** security
**Impact:** 4
**Effort:** 1
**Rationale:** The June/July 2026 Node.js security releases fix multiple HIGH-severity issues directly relevant to a Backstage backend service — unbounded memory growth in `node:http2` clients (CVE-2026-48619, a DoS vector), a permission-model bypass (CVE-2026-48617), and an mTLS SNI authorization bypass (CVE-2026-48928) — landing in v22.23.2 and v24.18.1/v24.20.0. mctl-portal's `engines` field explicitly supports Node 22 and 24, so this is a direct architectural fit and a low-effort patch-version bump (no code changes expected). Applies to tenant `admins`; not a `labs` concern, and a security/runtime patch bump has no expected memory-footprint increase.
**Source:** Node.js June 2026 / July 2026 security releases, https://nodejs.org/en/blog/vulnerability/june-2026-security-releases and https://nodejs.org/en/blog/vulnerability/july-2026-security-releases (inbox `## Source: cve` and `## Source: github releases`).

### 3. playwright-test-locks-upgrade: Adopt Playwright v1.63.0 Test Locks for e2e suite
**Category:** feature (DX)
**Impact:** 2
**Effort:** 1
**Rationale:** Playwright is an explicit part of the mctl-portal stack (architecture.md lists it for e2e), and v1.63.0's "Test Locks" feature directly addresses cross-file/cross-worker concurrency conflicts in e2e runs — a genuine DX/CI-reliability win with minimal effort (dependency bump + optional lock annotations in existing specs). It is a dev-tooling-only change with no runtime/production footprint, so it carries no `labs` memory risk and does not touch any ADR-protected area (Backstage core, observability plugin).
**Source:** Playwright v1.63.0 release notes, https://github.com/microsoft/playwright/releases/latest (inbox `## Source: github releases`). Note: release page date looked stale/cached during fetch; spec-writer should re-confirm the version/date before finalizing the proposal.
