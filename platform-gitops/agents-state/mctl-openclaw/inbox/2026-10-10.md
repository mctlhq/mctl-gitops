## Top-3 (for spec-writer)

### 1. upgrade-to-2026-9-9-plan: Staged upgrade plan to openclaw 2026.9.9 with breaking-change checklist
**Category:** security
**Impact:** 5
**Effort:** 4
**Rationale:** 2026.9.9 is the newest release, and every deployed version we have on record predates the fixes for CVE-2026-41336 (fixed 2026.3.31) and the GHSA batch. The plan must cover the breaking changes (DB format, Telegram `/dashboard`, haiku alias, scheduled-job validation) and the intermediate 2026.9.5 + `doctor --fix` step. Rollout follows ADR-0001 order (`labs` → `admins` → `ovk`). It supersedes the earlier `openclaw-upstream-upgrade-assessment` target version.
**Source:** github releases (v2026.9.9 notes), cve (CVE-2026-41336).

### 2. upgrade-db-format-rollback-guard: Pre-upgrade state snapshot because the new DB format blocks downgrade
**Category:** refactor
**Impact:** 5
**Effort:** 2
**Rationale:** 2026.9.9 states downgrade is unsupported once the DB format migrates. Rollback for `ovk` therefore needs an S3 state snapshot taken beforehand, plus coordination with the s3-sync canary and restore-state probe (ADR-0002). This is additive and consistent with ADR-0002, and does not touch memory.
**Source:** github releases (v2026.9.9 breaking changes).

### 3. labs-plugin-reuse-memory-validation: Measure `labs` memory effect of the 2026.9.9 plugin-reuse change
**Category:** performance
**Impact:** 3
**Effort:** 1
**Rationale:** The release claims reduced memory when switching models, which could relieve `labs`. Because `labs` is close to its memory limit, a before/after measurement during the canary rollout is the guard. It is measurement only and adds no footprint.
**Source:** github releases (v2026.9.9 memory notes).
