## Tests

- [ ] T1. Propagation: using `tracetest.SpanRecorder` and the synthetic personas `Alice` and `Bob`, run end-to-end cases through the existing harnesses (`worker_e2e_test.go`, `worker_tools_e2e_test.go`, `worker_approval_e2e_test.go`): success with a tool, no-tool, denied tool (pin refusal), tool approval_pending, turn timeout, and a retry (release, then reclaim as attempt 2). Each case yields one trace per job, with the expected span names, parentage, attempt numbers and outcomes.
- [ ] T2. Untrusted metadata: a webhook request and run-loop requests carrying a forged `traceparent`, `tracestate` or `baggage` produce spans only under the stored server context. The forged trace id never appears.
- [ ] T3. Cross-principal isolation: concurrent jobs for `Alice` and `Bob` (worker `WithConcurrency(2)`) never share a trace id, and no span of one job is parented to the other's.
- [ ] T4. Redaction: walk every recorded span and its events. Every attribute key must be in the `runAttrs` allowlist. No attribute value may contain the fixture principal ids, message text, tool arguments, tool output or token strings. Also assert that downstream MCP requests (`connector/mcpclient_test.go`) carry no `traceparent`.
- [ ] T5. Bounded cardinality: gather the metrics registry after the T1 cases and assert that the label values of the new and extended families are subsets of the closed sets, with no id-like label.
- [ ] T6. Absent stage: a no-tool run observes no `tool` phase and no `tool_call` stage. A run whose reply has not been delivered yet observes no `delivery` phase. A run with an unknown `created_at` observes no `queue` or `total` phase. Nothing is observed as 0.
- [ ] T7. Unchanged semantics: the existing `internal/pa`, `internal/pa/connector`, `internal/pa/jobs`, `internal/db` and `internal/agentworker` suites pass with tracing on and with it off. One table-driven test asserts that the HTTP status codes, release modes and failure reasons are identical in both modes for the lease-short, lease-expired, fenced (`StillRunning`) and cancel cases.
- [ ] T8. Exporter failure: an exporter pointed at a blackholed endpoint does not add latency above a small bound to `serveClaim`, `serveReply` or `deliverItem`, and does not fail them.
- [ ] T9. Migration: `pa_jobs` migrates on SQLite and Postgres (the existing `internal/db` migration tests), and old rows read `''`.

## Rollback

- Tracing: set `PA_TRACING_ENABLED` to `"false"`, or `otel.enabled: false` in gitops. The provider becomes a no-op at the next restart. No code rollback is needed.
- Code: revert the PR(s). The `trace_context` column is additive and harmless to leave in place, and older binaries ignore it. Drop it in a later migration only if needed.
- Metrics: the new families disappear with the revert. `mctl_pa_run_phase_seconds` keeps its original labels apart from `delivery`, so dashboards built on the old phases keep working throughout.
