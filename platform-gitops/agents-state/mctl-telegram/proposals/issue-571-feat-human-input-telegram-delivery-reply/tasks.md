## Tests

- [ ] T1. Single-choice render: golden output contains the header, work ref, numbered options, deadline and answer syntax, and contains no unallowlisted DTO field. Free-text render: golden output.
- [ ] T2. Poll dedup: the same request listed 3 times, and again after a simulated restart (new Poller, same DB), yields exactly one `owner_notifications` row.
- [ ] T3. Exact binding: `/mctl input <code> 2` submits the request_id and request_hash of that code's row, with the option id at index 2. The Idempotency-Key is stable across redelivery of the same TG message.
- [ ] T4. Stale callback: a code for hash h1 after the request moved to h2. mctl-api answers `request_hash_mismatch`; the reply is "This question is no longer active." and the row becomes `superseded`.
- [ ] T5. Duplicate command and double answer: the second submit returns `already_answered`. It produces one platform write and the reply "Already answered."
- [ ] T6. Crash after enqueue, before send: `DeliverPending` retries with the same random_id. Crash after send: no resend.
- [ ] T7. API timeout after acceptance: the submit transport errors, `GetHumanInput` returns `answered`, and the reply renders the canonical answered state. When both calls fail, the reply is the "could not confirm" message, never success.
- [ ] T8. Expired, cancelled or superseded: a request disappearing from the list produces one "no longer active" follow-up and a terminal row. A new hash for the same request_id produces a new code and the old row becomes `superseded`.
- [ ] T9. Unauthorized or unlinked actor: 403 `not_eligible` on submit gives neutral wording with no policy detail. 403 `link_not_found` on poll makes the actor dormant with backoff.
- [ ] T10. Two concurrent respondents (two users, same request_id): the first is accepted and the second gets `request_not_active`, rendered neutrally. No local lock decides the winner.
- [ ] T11. Redaction and minimal context: render never includes the fields `prompt`, `reasoning` or `logs`, even if present in the DTO JSON. A slog capture during poll and answer contains no question, option or answer text.
- [ ] T12. Approval isolation: `/mctl input <valid approval code> yes` does not resolve an agent action. A fake `Executor` records zero `Approve`/`Reject` calls across the whole humaninput test suite. `/mctl approve <human-input code>` fails as not found.
- [ ] T13. Flag off: `HUMAN_INPUT_ENABLED=false` means no poller, `Router.Input` is nil, and `/mctl input` returns the unknown-command reply. A relay client test server sees zero requests.
- [ ] T14. Work-item correlation: a delivered request whose `work_item_id` matches a `work_item_bindings` row renders that ref, and `/mctl work status` remains the canonical inspection path.
- [ ] T15. The schema test asserts that `human_input_deliveries` has no text column besides ids, hash, code, kind, state, outcome and option ids.

## Rollback

Set `HUMAN_INPUT_ENABLED=false` (or unset it) and redeploy. The poller stops, `/mctl input` reverts to the unknown-command reply, and no outbound human-input calls are made. Pending human-input requests stay owned by mctl-api/Temporal and can be answered through the canonical path, so no workflow state is lost. The two new tables are additive and can be left in place. If they must be removed, drop `human_input_deliveries` and `human_input_actors` in a follow-up migration. Queued `owner_notifications` rows of kind `human_input` can be marked `failed` with one UPDATE. For a code-level rollback, revert the merge commit: the change is self-contained in `internal/humaninput`, additive `workctx` methods, and flag-gated wiring.
